# Unity 이식판 · Windows 실행 안내

기존 웹 시제품의 핵심 흐름을 Unity 네이티브 C#과 UGUI로 옮긴 첫 이식판입니다. 웹 브라우저나 WebView를 실행하는 방식이 아닙니다. 서버·API 키·외부 AI 실행 없이 플레이합니다.

## 열고 실행하기

1. Unity Hub에서 Unity **6 LTS**를 설치합니다. 프로젝트 기준 버전은 **6000.0.62f1**입니다. 같은 6000.0 LTS 계열을 권장하며, 다른 버전에서 업그레이드하면 원본을 별도 보관하세요.
2. 배포 ZIP을 압축 해제합니다. Git 저장소를 내려받았다면 `unity/CampusSurvival`이 프로젝트 폴더입니다.
3. Unity Hub → **Projects → Add → Add project from disk**에서 **CampusSurvival** 폴더를 선택합니다. `Assets`, `Packages`, `ProjectSettings`가 바로 들어 있는 폴더입니다.
4. 첫 임포트·패키지 설치가 끝날 때까지 기다립니다. 최초에는 Unity 패키지 다운로드를 위한 인터넷 연결이 필요할 수 있습니다. 플레이 중에는 필요 없습니다.
5. 최초 임포트 후 시작 장면을 자동으로 선택합니다(현재 장면에 저장하지 않은 수정이 있으면 바꾸지 않습니다). 상단 **Campus → Open Game Scene**으로도 열 수 있습니다. 실제 `Assets/Campus/Scenes/Campus.unity`와 시작 컴포넌트를 포함합니다. Game 탭에는 Play 전에도 배경·대화창 미리보기가 생성됩니다.
6. Unity 상단 **▶ Play**를 누르면 타이틀 화면이 나옵니다. **새 이야기 시작** 또는 자동 저장이 있을 때 **이어하기**를 선택합니다. UI·배경·인물·게임 상태는 시작 코드가 생성하므로 Inspector에 별도로 연결할 작업이 없습니다.

Game 탭은 우선 **1440×900** 또는 **16:10**으로 검수하세요. 창 크기에 따라 UI가 조정되지만 Unity 실제 화면 검수는 아직 하지 않았습니다. Space는 본문 이어 읽기와 타이밍 입력에 사용하며, 선택지는 마우스로 고릅니다. 상단 메뉴·휴대폰은 전용 화면으로 전환됩니다.

## 기본 하늘만 보이는 경우 · 시작 화면 수정

이전 배포본은 빈 장면과 런타임 자동 생성 코드에 의존했고, Unity 실행 검수 없이 제공했습니다. 기본 카메라의 하늘만 나온다는 제보를 받아 아래를 수정했습니다. 제보 화면만으로 기존 문제의 정확한 오류 문장까지 확인한 것은 아닙니다.

- 시작 오브젝트의 스크립트 GUID를 연결한 `Campus.unity`를 배포본에 포함하고 빌드 시작 장면으로 등록했습니다.
- Play 전에도 같은 렌더러로 배경·대화창·선택지 미리보기를 만듭니다. 시작 장면 재생성 메뉴 `Campus → Repair Startup Scene`도 추가했습니다.
- 초기화 중 리소스/폰트/기타 오류가 나면 Console에 예외를 기록하고 화면에 오류·재시작 버튼을 표시합니다. 컴파일 오류로 스크립트 자체가 실행되지 않는 경우까지 이 화면을 표시할 수는 없습니다.
- 실제 시작에 성공하면 Console에 `Campus 시작 완료`가 표시됩니다.
- 인물의 위쪽이 화면 밖으로 잘리던 배치를 수정하고, 본문 클릭으로 이어 읽기를 추가했습니다.

업데이트 ZIP은 **새 폴더에 압축 해제**하고, Unity Hub에서 그 안의 **CampusSurvival** 폴더를 추가해 여세요. 이 폴더 바로 아래에 `Assets`, `Packages`, `ProjectSettings`가 있어야 합니다. 기존 Unity 프로젝트에 ZIP 전체를 폴더로 넣는 방식으로 설치하지 마세요. 기존 수동 저장은 별도 LocalLow 폴더에 남습니다.

**Campus → Open Game Scene** 후 Game 탭에서 배경과 대화창이 보이는지 확인하고 Play를 누르세요. Hierarchy에는 `Campus Survival`과 그 아래 `Canvas`가 있어야 합니다. 여전히 기본 하늘만 보이면 Console의 **첫 빨간 오류**를 확인하세요. `Campus` 메뉴 자체가 없으면 프로젝트 폴더/스크립트 임포트/컴파일부터 확인해야 합니다.

실행 후 **Campus → Check Current UI**를 선택하면 현재 Editor에서 활성 Canvas·글자·폰트·버튼·배경 생성 여부를 확인합니다. 이 메뉴는 사용자 컴퓨터의 Unity에서 실행하는 검사이며, 클라우드에서 실행했다고 주장하지 않습니다.

## 비주얼 노벨 연출과 화면

이번 프레젠테이션 개편은 기존 C# 게임 규칙을 유지하면서 Unity UGUI 렌더러를 교체합니다. 에디터 버전은 **6000.0.62f1** 그대로입니다.

- **새 인물 스프라이트:** 기존 얼굴·의상·헤어를 참고해 만든 투명 배경 4열×3행 아틀라스. 4명에게 각각 평상·생각·단호한 표현을 적용합니다. 텍스처의 원래 비율을 유지하도록 NPOT 자동 변환을 끕니다. 사각 배경 없이 배경 위에 배치하며, 표정 전환은 페이드로 연결합니다. 3D 모델·Live2D·립싱크는 아닙니다.
- **VN 대화 화면:** 작은 상단 HUD, 이름표, 남색 대화창과 아이보리 본문, 최대 3개 선택지, 읽은 뒤 등장하는 선택지와 호버 반응. 배경·인물 노드는 문장을 넘길 때마다 다시 만들지 않습니다.
- **읽기:** 대사 타이핑, 클릭/Space로 현재 문장 완성 → 다음 문장, AUTO, 실제로 읽은 문장만 남기는 대화 기록. AUTO는 선택지를 실행하지 않고 미니게임 입력도 대신하지 않습니다.
- **일시정지:** 메뉴·휴대폰에서 타이핑이 멈추고 읽던 문장/표시 위치를 복원합니다. H 또는 하단 UI 숨김으로 그림을 볼 수 있으며, 숨긴 동안 읽기와 입력 게임도 멈춥니다.
- **시작/저장/설정:** 타이틀의 새 이야기·이어하기·저장 불러오기, 자동+수동 3슬롯, 대사 속도·움직임 줄이기·버튼 효과음 설정. 효과음은 짧은 합성 UI음이며 음악·캐릭터 음성은 포함하지 않습니다.
- **생활 화면:** 휴대폰 앱 그리드와 밝은 커뮤니티, 시간표·연락처·기록 카드, 장소 검색, 호실 검색·층별 필터, 약속 제안별 응답. 검색·필터·메뉴 자체에는 게임 시간 비용이 없습니다.

코드는 `CampusApp.cs`(초기화·입력·저장), `CampusPresentation.cs`(화면), `VnUiMotion.cs`(등장/호버), `VnPresentationModel.cs`(읽기·배치 계산)로 나눴습니다. `Assets/Campus/Resources/Art/StandSprites.png`는 새 투명 인물 자산입니다.

상단 **Campus → Preview → Conversation / Phone / Cafe**는 Editor에서 확인하는 표시용 시안입니다. 이 명령으로 실제 저장 파일을 수정하지 않습니다. Play를 시작하면 타이틀에서 정상 진행합니다.

[대화 화면 참고 이미지](../docs/assets/vn-quality-layout-preview.png) · [휴대폰 참고 이미지](../docs/assets/vn-quality-phone-preview.png)

위 두 PNG는 같은 배치 계산값과 실제 자산을 사용해 브라우저로 렌더링한 **정적 디자인 참고 이미지**입니다. Unity 실행 캡처가 아닙니다. 타이핑·페이드·호버·실제 UGUI 배치는 사용자 컴퓨터의 Editor에서 검수해야 합니다. 이 클라우드에는 Unity Editor가 없으며, 이를 실행 검증 완료로 표현하지 않습니다.

## 인물 표시와 선택지 정리

일반 장면·수업에는 김태이의 정면 일러스트를 표시합니다. 실제 조우와 대화에서는 현재 그 장소에 있는 상대의 일러스트로 전환하며, 이름을 배우기 전에는 인상으로만 표기합니다. 카페·농구·요리·운반은 해당 CG 안의 인물을 사용합니다. 상단 이동/메뉴/휴대폰 화면에서는 장면 일러스트를 가립니다.

장면 선택은 **최대 3개**이고 더 많은 선택을 순환하는 버튼을 없앴습니다. 수업·약속·현장 활동처럼 지금 가능한 일을 우선 표시합니다. 상단 **이동**으로 장소를 고르며, 호실·우산·추가 대기·동선 재확인 등은 **메뉴 → 지금 이 장소에서**로 옮겼습니다. 메뉴를 여는 것에는 시간 비용이 없고 실제 행동을 고르면 장면으로 돌아와 결과가 표시됩니다.

- 상대의 여유를 먼저 묻기: 신뢰에 반영하며 같은 인물에게 같은 날 반복해도 추가 보상이 없습니다.
- 하던 일·말의 의미를 묻기: 실제로 들은 내용을 정보에 남깁니다.
- 내 음악 이야기를 꺼내기: 그 말을 들은 상대만 기억하며 친밀도와 기존 신뢰에 따른 호감에 반영합니다.
- 일반 대화는 한 주제를 몇 차례 나눈 뒤 마치거나 다음 만남/공동 경험 이야기로 넘어갑니다. 동일한 후속 질문을 끝없이 반복하는 흐름을 줄였습니다.
- 수업에서 호흡을 맞추는 메모와 프레이징 메모는 이후 공개 합주의 대응 접근에 각각 반영됩니다.
- 운동·혼자 떠맡은 운반 등에 따른 태이의 피로가 쌓이고, 휴식으로 줄어듭니다. 누적 피로는 타이밍 결과에 영향을 주며, 준비 단계에서 협력하는 선택은 입력 허용 폭에 반영됩니다.

이 변경은 모든 선택을 큰 사건 분기로 확장했다는 뜻은 아닙니다. 현재 이식된 일상 흐름 안에서 정보·개인 기억·관계·시간·피로·활동 결과의 차이를 구분했습니다. 실제 Unity 화면 검수는 계속 사용자 컴퓨터에서 필요합니다. 에디터 기준 버전은 **6000.0.62f1**로 유지합니다.

## 웹판과의 차이 및 남은 일

**기존 JavaScript 구현 전체를 1:1 변환한 완성판은 아닙니다.** 세계 데이터는 재사용하지만 C# 규칙과 UI를 새로 작성했습니다. Unity 쪽 세부 사건·분기·대사의 양은 웹보다 적으며 일부 활동은 공통 3단계 구조를 사용합니다. 웹과 Unity는 현재 별도 구현이므로 이후 기능 수정은 각각 반영해야 합니다. 웹 저장과 Unity 저장은 호환되지 않습니다.

- 자체 모델 서버 연결, 웹의 모든 대사·소문 전파·점심 사건·세부 위험 판단 분기는 아직 이식하지 않았습니다. Unity 대화는 로컬 조합 방식이며 실제 생성형 AI가 아닙니다.
- 인물의 이동은 시간표와 시간 구간으로 정합니다. 범용 AI 계획기나 실시간 3D 보행은 아닙니다.
- NPC 간 관계는 봉사 사건의 공동 경험과 다음 날 동선에 적용하는 제한된 구현입니다. 모든 NPC 조합의 자율 생활 시뮬레이션은 아닙니다.
- 배우는 이름과 직접 경험은 구분하지만 전공·나이·말 놓기 동의 등의 상세 지식 해금은 추가 구현이 필요합니다. 초면부터 `선배`라고 부르지 않습니다.
- 활동에 CG를 재사용하며, 3D 모델·애니메이션·입 모양·모든 표정별 새 일러스트는 없습니다. 건물별 내부 배경도 아직 별도 제작하지 않았습니다.
- 3일차 이상징후까지만 다룹니다. 좀비 전투·탈출·민간인 합류·추가 주인공 해금·외형 커스터마이징은 향후 개발 범위입니다.
- Unity Editor 실행·UGUI 화면·Windows 실행 파일 빌드는 이 클라우드에 Editor가 없어 **미검수**입니다. 코드 제공을 Windows 빌드 성공으로 간주하지 마세요.

## 권장 검수 순서

1. 시작 시 이름 없는 상태와 무소속 상태 → 예술동 409호 09:30 수업 → 401호 11:30 수업.
2. 휴대폰 커뮤니티에서 공지 읽기 → 자유관 현장에서 우연히 만남 → 직접 통성명. 대화 도중 메뉴를 열고 돌아오기.
3. 카페에서 결제 전 취소/실제 결제/수령/마시기. 정보·획득 알림과 지출·소지품 확인.
4. 동아리 신청 → 접수 30분 후 13–17시 자유관 해당 호실 면접 → 결과 30분 후 가입 결정.
5. 체육관 201호 농구 / 외식관 201호 요리 / 자유관 204호 운반. Space 입력·버튼 입력·일시정지·저장 후 재개.
6. 1일차 13–16시 자유관 봉사 준비에서 분담과 혼자 처리 비교 → 귀가 → 다음 날 휴대폰 제안 → 수락 후 실제 장소에서 20분 교류.
7. 수업 불참·약속 거절·수락 후 미이행·NPC 수업 중 대화 거절·3일차 종료 확인.

저장 위치는 Windows의 `%USERPROFILE%\AppData\LocalLow\CampusStudio\Campus Survival`입니다. `campus-slot-0.json`은 자동 저장, 1~3은 수동 저장이며 `.bak`은 직전 백업입니다. 브라우저 저장과 별개입니다. 새 회차 시작은 수동 슬롯을 지우지 않습니다.

## Windows 실행 파일 만들기

Unity 메뉴 **Campus → Build Windows**를 선택합니다. 필요한 Windows 빌드 지원 모듈이 설치되어 있어야 합니다. 성공하면 `CampusSurvival/Builds/Windows/CampusSurvival.exe`와 데이터 폴더가 생성됩니다. 배포할 때 `.exe`만 보내지 말고 해당 출력 폴더 전체를 함께 압축하세요.

PowerShell로 실행할 수도 있습니다. 경로는 설치한 버전에 맞춥니다.

```powershell
.\Tools\build-unity.ps1 -UnityEditor 'C:\Program Files\Unity\Hub\Editor\6000.0.62f1\Editor\Unity.exe' -Action Windows
```

이미 프로젝트를 열어둔 Unity와 배치 빌드를 동시에 실행하지 마세요. 로그는 `CampusSurvival/windows-build.log`입니다.

## 개발 구조와 검사

- `Assets/Campus/Runtime/CampusData.cs`: 저장 가능한 데이터 모델.
- `CampusEngine.cs`: Unity 의존성이 없는 게임 규칙과 화면별 가능한 행동. 오래된 버튼으로 결제·보상을 중복 처리하지 않게 검증합니다.
- `CampusApp.cs`: 초기화, 입력, 저장 파일 I/O.
- `CampusPresentation.cs`: Unity UI, 장면·인물·휴대폰·메뉴.
- `VnUiMotion.cs` / `VnPresentationModel.cs`: 전환/호버와 읽기·배치 계산.
- `Assets/Campus/Editor/CampusProject.cs`: 시작 장면 생성과 Windows 빌드 메뉴.
- `Assets/Campus/Resources/Data/world.json`: 게임용 건물/호실/시간표/공지 데이터.

저장소 루트에서 세계 데이터와 배포 ZIP을 갱신합니다.

```sh
node unity/Tools/export-world.mjs
python3 unity/Tools/package_project.py
```

.NET 8 SDK가 설치된 컴퓨터에서는 게임 규칙 테스트를 실행할 수 있습니다. 외부 NuGet 테스트 패키지는 필요하지 않습니다.

```sh
dotnet run --project unity/Tests/Campus.CoreChecks.csproj -- unity/CampusSurvival/Assets/Campus/Resources/Data/world.json
```

현재 **62개 검사**가 통과했습니다. 이 검사는 **순수 C# 로직 컴파일·테스트, 시작 장면/빌드 GUID 연결, Unity 연결 코드의 C# 문법 검사**입니다. Unicode 타이핑, 읽기 복원, AUTO 중단, 뷰포트 배치도 검사합니다. Unity API에 대한 컴파일, Play 모드, 그래픽 검수 또는 Windows 빌드를 대체하지 않습니다. `Korean.ttf`는 SIL OFL의 나눔고딕이며 라이선스를 함께 포함합니다. 그림은 이 저장소의 기존 시제품 자산을 재사용합니다.
