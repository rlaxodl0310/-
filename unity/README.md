# Unity 이식판 · Windows 실행 안내

기존 웹 시제품의 핵심 흐름을 Unity 네이티브 C#과 UGUI로 옮긴 첫 이식판입니다. 웹 브라우저나 WebView를 실행하는 방식이 아닙니다. 서버·API 키·외부 AI 실행 없이 플레이합니다.

## 열고 실행하기

1. Unity Hub에서 Unity **6 LTS**를 설치합니다. 프로젝트 기준 버전은 **6000.0.62f1**입니다. 같은 6000.0 LTS 계열을 권장하며, 다른 버전에서 업그레이드하면 원본을 별도 보관하세요.
2. 배포 ZIP을 압축 해제합니다. Git 저장소를 내려받았다면 `unity/CampusSurvival`이 프로젝트 폴더입니다.
3. Unity Hub → **Projects → Add → Add project from disk**에서 **CampusSurvival** 폴더를 선택합니다. `Assets`, `Packages`, `ProjectSettings`가 바로 들어 있는 폴더입니다.
4. 첫 임포트·패키지 설치가 끝날 때까지 기다립니다. 최초에는 Unity 패키지 다운로드를 위한 인터넷 연결이 필요할 수 있습니다. 플레이 중에는 필요 없습니다.
5. 상단 **Campus → Open Game Scene**을 선택합니다. 첫 임포트 시 빈 시작 장면도 자동 생성합니다.
6. Unity 상단 **▶ Play**를 누릅니다. UI·배경·초상화·게임 상태는 시작 코드가 생성하므로 Inspector에 별도로 연결할 작업이 없습니다.

Game 탭은 우선 **1440×900** 또는 **16:10**으로 검수하세요. 창 크기에 따라 UI가 조정되지만 Unity 실제 화면 검수는 아직 하지 않았습니다. Space는 본문 이어 읽기와 타이밍 입력에 사용하며, 선택지는 마우스로 고릅니다. 상단 메뉴·휴대폰은 전용 화면으로 전환됩니다.

## 웹판과의 차이 및 남은 일

**기존 JavaScript 구현 전체를 1:1 변환한 완성판은 아닙니다.** 세계 데이터는 재사용하지만 C# 규칙과 UI를 새로 작성했습니다. Unity 쪽 세부 사건·분기·대사의 양은 웹보다 적으며 일부 활동은 공통 3단계 구조를 사용합니다. 웹과 Unity는 현재 별도 구현이므로 이후 기능 수정은 각각 반영해야 합니다. 웹 저장과 Unity 저장은 호환되지 않습니다.

- 자체 모델 서버 연결, 웹의 모든 대사·소문 전파·점심 사건·세부 위험 판단 분기는 아직 이식하지 않았습니다. Unity 대화는 로컬 조합 방식이며 실제 생성형 AI가 아닙니다.
- 인물의 이동은 시간표와 시간 구간으로 정합니다. 범용 AI 계획기나 실시간 3D 보행은 아닙니다.
- NPC 간 관계는 봉사 사건의 공동 경험과 다음 날 동선에 적용하는 제한된 구현입니다. 모든 NPC 조합의 자율 생활 시뮬레이션은 아닙니다.
- 배우는 이름과 직접 경험은 구분하지만 전공·나이·말 놓기 동의 등의 상세 지식 해금은 추가 구현이 필요합니다. 초면부터 `선배`라고 부르지 않습니다.
- 활동에 CG를 재사용하며, 3D 모델·애니메이션·입 모양·모든 표정별 새 일러스트는 없습니다. 건물별 내부 배경도 아직 별도 제작하지 않았습니다.
- 3일차 이상징후까지만 다룹니다. 좀비 전투·탈출·민간인 합류·추가 주인공 해금·외형 커스터마이징은 향후 개발 범위입니다.
- Unity Editor 실행·UGUI 화면·Windows 실행 파일 빌드는 이 클라우드에 Editor가 없어 **미검수**입니다. 코드 제공을 Windows 빌드 성공으로 간주하지 마세요.

## 권장 검수 순서

1. 시작 시 이름 없는 상태와 무소속 상태 → 예술동 409호 09:30 수업 → 401호 11:30 수업.
2. 휴대폰 커뮤니티에서 공지 읽기 → 자유관 현장에서 우연히 만남 → 직접 통성명. 대화 도중 메뉴를 열고 돌아오기.
3. 카페에서 결제 전 취소/실제 결제/수령/마시기. 정보·획득 알림과 지출·소지품 확인.
4. 동아리 신청 → 접수 30분 후 13–17시 자유관 해당 호실 면접 → 결과 30분 후 가입 결정.
5. 체육관 201호 농구 / 외식관 201호 요리 / 자유관 204호 운반. Space 입력·버튼 입력·일시정지·저장 후 재개.
6. 1일차 13–16시 자유관 봉사 준비에서 분담과 혼자 처리 비교 → 귀가 → 다음 날 휴대폰 제안 → 수락 후 실제 장소에서 20분 교류.
7. 수업 불참·약속 거절·수락 후 미이행·NPC 수업 중 대화 거절·3일차 종료 확인.

저장 위치는 Windows의 `%USERPROFILE%\AppData\LocalLow\CampusStudio\Campus Survival`입니다. `campus-slot-0.json`은 자동 저장, 1~3은 수동 저장이며 `.bak`은 직전 백업입니다. 브라우저 저장과 별개입니다. 새 회차 시작은 수동 슬롯을 지우지 않습니다.

## Windows 실행 파일 만들기

Unity 메뉴 **Campus → Build Windows**를 선택합니다. 필요한 Windows 빌드 지원 모듈이 설치되어 있어야 합니다. 성공하면 `CampusSurvival/Builds/Windows/CampusSurvival.exe`와 데이터 폴더가 생성됩니다. 배포할 때 `.exe`만 보내지 말고 해당 출력 폴더 전체를 함께 압축하세요.

PowerShell로 실행할 수도 있습니다. 경로는 설치한 버전에 맞춥니다.

```powershell
.\Tools\build-unity.ps1 -UnityEditor 'C:\Program Files\Unity\Hub\Editor\6000.0.62f1\Editor\Unity.exe' -Action Windows
```

이미 프로젝트를 열어둔 Unity와 배치 빌드를 동시에 실행하지 마세요. 로그는 `CampusSurvival/windows-build.log`입니다.

## 개발 구조와 검사

- `Assets/Campus/Runtime/CampusData.cs`: 저장 가능한 데이터 모델.
- `CampusEngine.cs`: Unity 의존성이 없는 게임 규칙과 화면별 가능한 행동. 오래된 버튼으로 결제·보상을 중복 처리하지 않게 검증합니다.
- `CampusApp.cs`: Unity UI, 아트 표시, 입력, 저장 파일 I/O.
- `Assets/Campus/Editor/CampusProject.cs`: 시작 장면 생성과 Windows 빌드 메뉴.
- `Assets/Campus/Resources/Data/world.json`: 게임용 건물/호실/시간표/공지 데이터.

저장소 루트에서 세계 데이터와 배포 ZIP을 갱신합니다.

```sh
node unity/Tools/export-world.mjs
python3 unity/Tools/package_project.py
```

.NET 8 SDK가 설치된 컴퓨터에서는 게임 규칙 테스트를 실행할 수 있습니다. 외부 NuGet 테스트 패키지는 필요하지 않습니다.

```sh
dotnet run --project unity/Tests/Campus.CoreChecks.csproj -- unity/CampusSurvival/Assets/Campus/Resources/Data/world.json
```

현재 **41개 검사**가 통과했습니다. 이 검사는 **순수 C# 로직 컴파일·테스트와 Unity 연결 코드의 C# 문법 검사**입니다. Unity API에 대한 컴파일, Play 모드, 그래픽 검수 또는 Windows 빌드를 대체하지 않습니다. `Korean.ttf`는 SIL OFL의 나눔고딕이며 라이선스를 함께 포함합니다. 그림은 이 저장소의 기존 시제품 자산을 재사용합니다.
