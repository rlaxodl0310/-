# 확정 전투 공식과 구현 경계 · v0.28.0

2026-11-21 사용자가 이 대화의 전투 규칙을 확정하고 기록/게임/AI 반영을 요청했다. 아래 확정 규칙과 미정 부분을 메우는 구현값을 구분한다. 공식 계산은 `ui/combat/rules.js`가 담당하고 일반 전투와 실시간 전투, 기존 격자 시험장의 기본 피해 판정이 같은 모듈을 사용한다. 격자 시험장의 장비 시험 기술은 별도 시제품 데이터다.

## 피해와 레벨

`기본 공격 위력 = 기본 위력 + 관련 공격력 × 기술 계수`이다. 장비/무기의 기본 위력과 캐릭터의 실제 공격용 수치를 입력한다. 체력/마나 스탯을 공격력으로 자동 전환하지 않는다. 일시적인 공격 강화는 공격 기여분에 한 번만 합산 적용한다.

`방어 보정 = 100 / (100 + 유효 방어력)`이다. 레벨 보정은 `1 + max(0, 공격자 레벨 - 대상 레벨) × 0.01`이다. 7레벨→1레벨은 +6%, 반대 방향에 추가 피해 감소는 없다. 레벨이 높다고 스탯 상승을 과장하지 않는다. 같은 등급이라도 스킬 조합·장비·정수가 중요하다.

연타는 타격마다 실제 계수와 치명타/급소/부위/보호막을 따로 판정한다. `0.33 × 3`은 총0.99이다. 먼저 총피해나 치명타 한 번을 계산해 나누지 않는다. 임의로 각 타격을 최소1 또는 정수로 올려 총량을 부풀리지 않는다. 내부 계산은 소수로 보존하고 표시만 정리한다.

## 부위 방호와 공략

갑옷의 `damageReduction`은 피격 부위에만 적용한다. 견갑33%는 어깨의 최종 피해에0.67을 곱한다. 다른 부위에는 견갑 방호가 없다. 현재 부위는 명시적인 지정을 쓰며 미지정은 몸통이다. 정밀한 신체별 충돌 메시/부위 명중률 시스템을 완성했다는 의미는 아니다. 그림에 견갑이 보인다는 이유로 수치를 자동 지급하지 않는다.

공략 점수 `A = 공격력 × (1 + 급소 적중률) × 스킬 급소 계수`, 저항 점수 `D = 방어력 × (1 + 피격 부위 피해감소율)`이다. `E = (A-D)/(A+D)`이며 둘 다0이면E=0이다. 비율은33%=0.33처럼 입력한다.

- 부위 방어구 있음: `clamp(0.5+E,0.05,0.95)` 확률로 해당 부위 피해감소만 우회한다. 방어력은 제거하지 않는다.
- 부위 방어구 없음: `max(0,E)`를 추가 피해율로 적용한다. 이것은100%를 넘는 급소 확률이 아니라 상대 공략 저항과 비교해 남은 수치다.
- 치명타와 부위 방호 우회는 별개이며 타격마다 독립 난수를 쓴다. 골절/출혈 등은 이 계산만으로 자동 확정하지 않는다.

비율 방어 관통과 고정 방어 관통은 둘 다 존재하고 방어력을0 미만으로 만들지 않는다. 두 종류의 적용 순서는 아직 사용자 미정 사항이다.

## 강화·약화·저항

동일한 실제 효과는 강한 것만 적용한다. 서로 다른 강화는 합산하며 이름만 바꾸어 같은 효과를 무한 중첩하지 않는다. 약한 효과로 강한 효과를 보충/연장하지 않는다. 남아 있는 약한 효과는 강한 효과 만료 뒤 자신의 남은 시간 동안 다시 작용한다.

일시 효과 상한은 공격/방어 +100%, 이동/공격/시전 속도 +50%, 공격/방어 약화 -50%, 둔화 -60%, 치유 감소75%, 일반 피해감소75%다. 부위 방어구의 피해감소는 별도이며, 명시된 무적/완전 차단/특수 고유 효과는 일반 피해감소로 취급하지 않는다.

디버프는 적용 저항과 지속시간 저항을 구분한다. 반복된 기절/속박/빙결 등의 강한 제어는100%→50%→25%→잠시 면역으로 줄인다. 피해 자체가 면역이 되지는 않는다. 해제는 가능한 효과 종류와 등급 한도를 검사하며 낮은 정화가 모든 저주를 없애지 않는다.

## 치유

기본 회복량은 스킬 기본값 + 치유력×계수다. 치유력은 별도의 투자 스탯으로 확정하지 않고 장비/정수/스킬의 회복용 수치로 취급한다. MP 기반 기본 효율은1~2등급2, 3~4등급2.5, 5~7등급3, 8~10등급3.5 HP/MP다.

`최종 회복 = 기본 회복 × clamp(1+치유 강화-치유 감소,0.25,2)`이다. 치유 강화 상한+100%, 감소 상한75%, 실제 결손 HP까지만 회복한다. 초과 회복은 별도 전환 효과가 없다면 버린다. MP24의2등급 마력 봉합은 기본HP48, 강화20%/감소30%라면43.2다.

지속 치유는 총기본량을 틱으로 나누고 실제 회복분만 기록한다. HP 회복은 골절/중독/절단을 자동 치료하거나 죽은 대상을 부활시키지 않는다. 자기HP 전달은 전달량을 증폭해 무한한 생명력을 만들지 않는다.

## 보호막

흡수형 기본량은 같은 등급 치유 기본 효율의1.25배 + 보호막 강화 수치×계수이고, 보호막 강화율을 적용한다. 기본8초. 다른 보호막은 별도 잔량으로 합산하되 일반 흡수형의 동시 총량은 최대HP50%까지다. 명시된 대형 장벽 등 예외는 별도 한도를 쓴다. 방어/레벨/치명타/급소/부위 방호 등을 계산한 뒤 보호막을 먼저 깎고 남는 피해가 HP로 간다. 방어구 우회가 보호막 우회는 아니다.

1회 차단형에는 유한한 방호 한계가 있다. 같은MP의 흡수형보다20% 높은 한계, 기본5초, 첫 유효 타격에 소모한다. 피해≤한계라면 완전 차단하고 적중 부가효과도 막는다. 초과하면 보호막이 깨지고 한계만큼만 줄인 나머지가 통과한다. 뚫린 타격의 부가효과는 별도 정상 판정이다. 빗나감/회피에는 횟수를 소모하지 않는다. 독무 같은 독립 환경 효과까지 삭제하지 않는다.

한계100에300피해면200통과. 80×3연타라면 첫80만 차단하고 나머지는 정상 판정이다. 앞서 제안한1.5배MP 요금은 이 유한 한계 방식에서 폐기했다.

## 미정 부분의 조정 가능한 구현값

다음은 편의를 위한 구현값이며 확정 세계법칙으로 기록하지 않는다.

- 비율 관통→고정 관통. 반대 순서도 함수가 지원한다.
- 치명타 기본1.5배. 치명타 확률은 실제 입력 수치를 쓰며 임의로 능력을 지급하지 않는다.
- 반복 제어 판단창10초, 일시 면역5초. 적용 확률과 지속시간 저항의 구체적인 수치식도 조정 대상이다.
- 동시에 있는1회형과 흡수형은1회형부터 소모한다. 명시된 예외가 없으면1회형을 무제한 비축하지 않는다.
- 지속 치유의 개별 틱 간격, 부위 미지정 시 몸통 사용, 장비별 공격력/방어력/급소 보정 수치.

## AI와 저장

`electron/combat-context.cjs`는 공식·상한·엔진으로 계산한 예제와 수치 인용 규격을 전달한다. AI는 실제 판정 뒤 묘사하며 `combatClaims`의 사건ID/피해/회복/차단/치명타/방호 우회/레벨 배율을 엔진 기록과 비교한다. 명시적인 피해/회복 숫자 표현도 일부 검사한다. 모든 자연어 모순을 증명하거나 모델 가중치를 재학습한 것은 아니다. 실제 ChatGPT의 응답 품질은 별도 확인 대상이다.

난수 상태·보호막 잔량·상태 지속시간과 판정 원문을 저장한다. 실패한 AI 검토는 피해·마나·난수·대화 턴을 저장하지 않는다. 시각 효과용 이벤트 링 버퍼와 별도 판정 기록을 사용해 연타/범위 공격의 앞 타격을 잃지 않는다. 반복 요청은 같은 저장과 난수 상태에서 재현한다. 전투 공식 검증실은 본편 저장을 변경하지 않는다.

## 기본 스탯 정정 · v0.29.0

사용자 확정 기본 스탯은 힘·민첩·방어력·마법 공격력·마법 저항력·체력·마나, 총7개다. 급소 적중률은 개별 스킬 옵션이며 기본 스탯이나 인물 공통 수치로 적용하지 않는다. 치유력·보호막 강화·치명타 보정 등은 별도 효과 수치다.

물리 공격은 힘, 마법 공격은 마법 공격력을 참조한다. 물리는 방어력, 마법은 마법 저항력으로 방어한다. 다른 유형의 스탯을 대신 참조하지 않는다. 체력1=최대HP100, 마나1=최대MP100을 유지한다. 민첩은 기존 실시간 이동·준비 동작·회피 충전 계산에 연결하며 이번 수정으로 새 성장 계수를 확정하지 않는다. 미정 기본 수치는 UI에 미확인으로 표시하고 임의 지급하지 않는다.

`ui/combat/stats.js`가 이름·검증·이전 저장 변환을 공유한다. 새 배분은7개의 정식 키만 허용한다. 예전 attack/intelligence/magicDefense는 각각 힘/마법 공격력/마법 저항력으로 호환하며 정식 키 값이 있으면 우선한다. 이전 급소 공통값은 비활성 보관하고 어느 스킬에도 자동 지급하지 않는다. 자원과 저장 기록은 보존한다. AI에는 같은7개 스탯과 역할을 전달한다. 모델 가중치 재학습은 아니다.

## 출처별 능력치 · v0.30.0

`ui/progression/model.js`는 기본/배분/정수/장비를 보존하고 영구 합계를 재계산한다. 일시 효과는 기존 CombatRules가 적용하며 상태창은 같은 계산을 표시한다. 저장의 이전 합계를 다음 계산의 기본값으로 쓰지 않는다. 장비 파손은 전투의 wearWeapon에서 즉시 재계산하고 본편 복귀 때 내구도를 검증·보존한다.

체력/마나 보너스를 착탈해도 현재HP/MP는 늘지 않는다. 최대치가 줄 때만 초과 잔량을 잘라내므로 교체로 회복할 수 없다. 부위 방호가 겹치면 가장 강한 값을 채택하는 것은 조정 가능한 구현 선택이다.

본편 내 정보의 장비/흡수/배분은 director:progression을 거쳐 소유권·슬롯·소멸·요청ID·버전을 검사한다. 아이템 전체 정의를 IPC로 받을 수 없다. grantReward는 기존 사건을 요구하는 내부 획득 경로이며 자동 드랍률/상점 재고는 아직 연결하지 않았다. 정수 액티브의 미정 비용·등급·판정은 실행하지 않고 설명과 출처를 등록한다. 장비 스킬은 등록된 공용 도감ID를 참조하며 장비 해제 시 보관된 숙련을 지우지 않는다.

## 성장 통합 검증 · v0.31.0

확정된 레벨 상승당3포인트는 Progression.awardLevel의 내부 보상으로 반영한다. 요청ID 중복·하락·포인트 오버플로를 검사하며 수치는 스탯 배분 전까지 변하지 않는다. HP/MP도 회복하지 않는다. 성장→배분→흡수→착용→실제 공용 스킬/피해→디스크 저장/복구를 tests/growth-integration.test.cjs에서 확인한다. 검증실의 버튼은 별도 시험 인물을 쓰며 본편 저장에 영향을 주지 않는다.

level-draft.js는 검증실 전용 제안이다. ceil(100×L^1.6/10)×10을 다음 레벨 필요량으로 사용하고 초과 경험치를 이월한다. 실제 StoryDirector는 이를 import하지 않으며 처치/의뢰 경험치를 지급하지 않는다. 곡선과 보상 기준은 사용자 확정 이후 본편에 연결한다.
