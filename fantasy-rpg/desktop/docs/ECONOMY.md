# 화폐·의뢰 경제 v0.7.0

금액의 저장·계산 단위는 동화 정수다. 동화 100=은화 1, 은화 1,000=금화 1, 금화 100=백금화 1이다. 부동소수점 환산, 음수 잔액, 안전 범위를 넘는 금액은 거부한다.

`ui/association/economy.js`가 물가·일당·환산·의뢰 비용·장부를 담당한다. `quests.js`는 게시·수락·만료·정산을 연결한다. AI는 의뢰의 제목과 설명만 작성하며 보수·예산·인원·정산 증빙을 결정하지 않는다.

## 사용 방법과 범위

앱 상단 **의뢰 테스트**에서 종이 의뢰를 열어 총보수와 인원별 예상 분배를 확인한다. 수락한 뒤 닫고 **게시판 테스트 설정 → 개발용 경제 모의 → 선택 의뢰 완료 모의 정산**을 누르면 계약 기간이 흐르고 예상 비용을 공금에서 지불한 뒤 예치금을 정산한다. 생활비 모의 지불과 보유 재료 매각도 지원한다.

이는 기존 본편과 분리된 게시판 테스트 저장이다. 시험 파티 공금은 태이 개인 소지금이 아니다. 공금 300동화, 협회 예산 5,000동화, 상인 자금 3,000동화 및 재료 견본은 시연 초기값이며 세계 전체의 자산 설정이 아니다. 본편 전투·실제 납품 판정, 캐릭터별 분배 계좌, 상점 장비 구매 및 포션 사용 효과는 아직 연결하지 않았다. 실제 플레이가 완료됐다고 AI가 서술하는 것만으로 지급하지 않는다.

## 거래와 보전

- 의뢰 게시 시 계약 총보수와 재료비 상한을 발주자의 기존 자금에서 예치한다. 자금이 부족하면 게시를 보류한다.
- 계약은 파티 하나의 총액이다. 같은 던전에서 여러 파티가 활동하더라도 각자 별도의 계약을 체결한다.
- 순익은 총보수+증빙 재료비 환급−실제 공통 비용이다. 개인 몫은 이를 인원수로 나눈 계산값이고, 남은 동화는 공금에 남긴다.
- 모의 완료는 Electron 서비스가 생성한 시험 증빙만 사용한다. 수행 기간·기한·비용·납품 물품을 검증하며 중복 정산은 잔액과 시간을 바꾸지 않는다.
- 만료 시 미지급 예치금을 반환한다. 시간이 흐르거나 앱을 다시 열어도 예산과 재고는 자동 충전되지 않는다.
- 납품에 묶인 물품은 매각 가능 재고에서 제외하고 인계 시 실제 재고를 소비한다.
- 재료 매입에는 상인의 가용 현금과 잔여 수요 한도가 있다. 매입 재고가 늘면 단가가 낮아진다. 나눠 팔아도 일괄 매각과 같은 총액이다.
- 모든 자금 이동 전후에 공금+발주자 잔액+예치금+서비스 제공자 수입의 합계를 검증한다.

## 설정 기준과 시연 수치

기본 도시 물가와 주요 호위·토벌·조달 보수는 WORLD_BIBLE 53절의 승인된 기준을 사용한다. 던전·조사·채굴·구조의 구체 보수, 모든 예상 공통 비용, 재료 견본 매입가, 지역 할증 계수는 테스트용 조정값이다. 고정된 세계관 법칙으로 확정하지 않는다. 교역로는 운송료 25%, 신규 던전은 숙박·포션 25%, 붕괴 철수는 식사·숙박·운송 50% 할증을 시연한다.

아티팩트·영혼석에는 고정 소매 정가를 부여하지 않는다. 정수의 30분 소멸 규칙을 일반 재료 재고로 대체하지 않는다.

## 저장 이전

이전 v1 의뢰 테스트 저장은 상태와 수락 여부를 유지하며 단위 없는 임시 보수를 새 동화 계약으로 이전한다. 실제 저장을 갱신하기 전에 `.v1-backup`을 한 번 생성한다. 이전 보수는 `legacyReward`에 보존한다. 수락된 계약에 우선 예치하고 예산이 부족한 계약은 재예치 대기로 둔다. 본편 저장·로그인 정보는 건드리지 않는다. 읽을 수 없는 저장은 자동 초기화하거나 덮어쓰지 않는다.

## 검증
