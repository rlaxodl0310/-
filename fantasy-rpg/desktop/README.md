# v0.3.0 · AI 전투 행동 판단

브라우저 사이트 단독으로는 이 구독 연결을 사용할 수 없습니다. Windows 앱 내부의 전투 테스트에서 사용하세요. 본편 현실 도입부와 전투 저장은 별도입니다.

# 이세계 기록 — Electron 앱 시제품

기존 비주얼 노벨 화면을 재사용한 Windows x64 데스크톱 앱입니다. **Python·별도 Node 설치·브라우저 모델 다운로드 없이** 실행하도록 Electron과 공식 Codex CLI를 함께 묶습니다. ChatGPT 구독 계정으로 공식 인증 화면에 로그인하여 캐릭터와 대화합니다. FMAX의 내부 구현을 복제하거나 확인한 것은 아닙니다.

## Windows 실행

1. Windows 실행본 ZIP을 **폴더 전체로 압축 해제**합니다.
2. `FantasyStory.exe`를 실행합니다. exe만 다른 곳으로 옮기지 않습니다.
3. 상단 **ChatGPT 연결 → ChatGPT로 로그인**을 누릅니다.
4. 공식 OpenAI 브라우저 창에서 로그인합니다. 창이 열리지 않으면 앱의 **공식 로그인 페이지 열기**를 누릅니다.
5. **로그인됨/연결됨** 표시 후 채팅창에 입력합니다.

일반 브라우저 인증이 어려운 경우 **인증 코드로 로그인**을 선택할 수 있습니다. 공식 페이지에 앱에 표시된 코드를 입력하며, 계정에 따라 코드 인증 허용 설정이 필요할 수 있습니다. 실패 시 앱에 안내합니다. 비밀번호를 앱에 입력하지 않습니다.

이 앱은 서명 전 시제품입니다. Windows 실기기·공식 계정의 신규 로그인과 실제 모델 응답은 별도 검증이 필요합니다. Electron 앱 화면 및 IPC는 Linux의 실제 Electron에서 시험용 CLI를 사용해 검사했습니다.

## AI와 비용

- 공식 Codex CLI 0.169.0, Electron 45.3.3을 묶습니다. 구독의 Codex 사용량·계정별 한도가 적용됩니다. 앱이 API 키를 요구하거나 자동으로 유료 API로 전환하지 않습니다. 무제한 이용을 뜻하지 않습니다.
- 인증과 토큰 관리는 공식 Codex가 담당합니다. 앱은 인증 파일을 열거나 복사하지 않습니다. 기존 Codex 로그인과 같은 계정을 사용할 수 있습니다.
- 현재 인물·현 장면과 같은 장면의 대화는 Codex를 통해 OpenAI로 전송됩니다. 앱이 자체적으로 ChatGPT 웹페이지를 자동 조작하지 않습니다.
- 내장 CLI가 실행되지 않으면 연결 메뉴에서 공식 `codex.exe` 경로를 선택할 수 있습니다. npm 개발 실행에서도 공식 Codex 플랫폼 패키지를 사용합니다.
- Codex 기본 모델을 사용하며 고정 모델명을 가정하지 않습니다. 로그인 상태가 확인됐다고 실제 모델 응답 성공까지 검증됐다는 뜻은 아닙니다.

## 게임과 저장

현실 지하철 도입부 3장면·6선택 경로, 컷신·SD, 상태창, 인물 제작실, 대화 기록, 자동 저장·수동 슬롯 3개·게임 JSON 내보내기를 유지합니다. 상태창 숫자는 화면 시험용 값이며 본편 사건 순서·동행·장비 획득을 확정하지 않습니다.

AI 기억은 OS 앱 사용자 데이터 폴더의 `ai-dialogue.json`에 저장합니다. 장면별 40회, 전체 400회까지 보존하며 실패한 요청은 반영하지 않습니다. 동일 요청 번호는 저장된 답변을 재사용합니다. AI 기억 초기화는 게임 저장 슬롯과 별개이고 게임 JSON 파일에 AI 기억/인증은 포함되지 않습니다.

창을 닫거나 ■ 버튼을 누르면 진행 중인 Codex 자식 프로세스를 종료합니다. 실패·취소 시 입력을 유지합니다. 이미 처리된 요청의 구독 사용량은 발생했을 수 있습니다. 실제 AI 연결 실패를 가짜 AI 답변으로 바꾸지 않으며, 작성형 체험 모드는 명시적으로 선택합니다.

모델은 인물의 대사와 짧은 동작만 반환합니다. 스탯·정수·시간·아이템·이벤트 완료는 모델이 변경할 수 없습니다. 작가용 설정집 전체와 제로의 숨은 정체는 프롬프트에 넣지 않습니다. 실제 전투·레벨 상승·정수 타이머·즉석 이미지 생성은 아직 구현하지 않았습니다.

## 구조

- `electron/main.cjs`: 앱 창, 제한된 IPC, 공식 인증 페이지 열기, CLI 파일 선택.
- `electron/preload.cjs`: 정해진 연결 메서드만 화면에 노출. Node 통합은 끄고 context isolation과 renderer sandbox를 사용합니다.
- `electron/codex.cjs`: shell:false 자식 프로세스, stdin 프롬프트, 읽기 전용·일회성 실행·도구 비활성화 옵션, 출력 제한·취소·JSON 검증.
- `electron/dialogue.cjs`: 장면별 프롬프트·대화 기억·중복 요청 처리·성공 후 원자적 저장.
- `ui/`: 기존 게임 UI와 Electron용 연결 어댑터. 렌더러는 임의 파일·명령·외부 모델 API에 접근하지 못합니다.

도구 호출 이벤트는 답변으로 적용하지 않지만 CLI 실행 옵션을 OS 수준의 완전한 격리나 모델의 사실 검증으로 표현하지 않습니다.

## 개발과 패키징

Node.js 22 이상에서 `npm ci`, `npm test`, `npm start`로 실행합니다. 다운로드할 공식 Electron/Codex 배포본이 크므로 처음 설치에는 시간이 필요합니다. 개발 중 `FANTASY_CODEX_BIN`으로 공식 네이티브 CLI를 지정할 수도 있습니다.

Windows 패키징에는 공식 npm 배포본 `@openai/codex@0.169.0-win32-x64`의 `vendor/x86_64-pc-windows-msvc` 내용을 `vendor/codex-win32-x64`에 준비하고 `npm run package:win`을 실행합니다. Electron ZIP 캐시가 있으면 `FANTASY_ELECTRON_ZIP_DIR`을 지정할 수 있습니다. 결과는 `release/FantasyStory-win32-x64`입니다. 실행본과 로그인 토큰을 Git에 커밋하지 않습니다.

`npm test`의 17개 검사는 구독 인증 판별·API 키 경로 배제·실제 자식 프로세스 입출력·취소·JSON/도구 이벤트 거부·기억·중복 요청·게임 분기를 확인합니다. 실제 Electron 테스트는 `tests/smoke.cjs`로 격리된 임시 프로필과 시험용 CLI를 사용해 렌더러의 Node 비노출, 로그인 IPC, 채팅, 저장 후 새로고침 복원을 확인합니다. 이는 실제 ChatGPT 계정 인증과 모델 응답 검증을 대신하지 않습니다.

공식 인증/이용 안내: https://developers.openai.com/codex/auth/ · https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan

Electron 라이선스와 Chromium 고지는 실행본에 포함하며 Codex는 Apache-2.0입니다. `licenses/`와 동봉된 공식 배포본의 NOTICE를 참고합니다.


## v0.2.0 · 플레이어 역할과 현실 도입부

- 김태이는 플레이어이며 NPC나 대화 상대로 등록하지 않습니다. AI는 현재 장면의 NPC만 연기합니다. 태이의 대사·생각·결정은 사용자가 정합니다.
- 현실의 등굣길 지하철에서 일상 대화부터 시작합니다. 도입부 3장면은 순서대로 열리며 아직 자동으로 이세계 전송을 일으키지 않습니다. 대화와 구체적인 도입 사건은 검토용 초안입니다.
- 현실에서는 레벨·마나·정수·제로 등 판타지 상태 정보를 표시하거나 인물에게 미리 알려주지 않습니다. 신규 일러스트 요청이 없어 중립적 배경과 기존 교복 초상을 사용합니다.
- 파티/동행 창은 실제로 함께 이동하기로 선택한 인물만 표시합니다. 모르는 나이는 확인하지 못한 것으로 두고 성격·특성·과거 설정을 나열하지 않습니다.
- 별도 캐릭터 도감은 전체 항목을 두되, 자신과 기존에 아는 여경·도겸의 기본 정보만 먼저 표시합니다. 아직 모르는 인물은 이름도 잠그고 known_person/known_age 해금 기록으로 정보를 엽니다. 도감 등록과 파티 합류는 별개입니다.
- 기존 v0.1 저장 키와 AI 기록은 삭제하지 않습니다. 새 스토리는 fantasy-desktop-story-v2 키와 새 장면 ID로 시작합니다. 옛 JSON을 새 스토리에 강제 변환하지 않습니다.

## 패치로 업데이트

기존 앱은 FantasyStory-Patch.zip을 폴더 전체로 압축 해제한 뒤 **게임 저장/종료 → FantasyStoryPatch.exe 실행 → 기존 FantasyStory.exe 폴더 선택**으로 업데이트합니다.

resources/app.asar만 교체하고 Electron·Codex·공식 로그인·앱 사용자 데이터는 교체하지 않습니다. SHA256 검사·버전 검사·기존 파일 백업·교체 실패 시 복원을 지원합니다. 백업은 resources에 남습니다. Windows 기본 .NET Framework로 실행하며 Python이나 별도 Node 설치가 필요 없습니다.

현재는 내려받은 패치를 직접 실행하는 방식입니다. 서버의 버전 확인과 자동 다운로드는 아직 구현하지 않았습니다. 체크섬은 파일 손상 검사용이며 디지털 서명을 대신하지 않습니다.

patch/PatchCore.cs가 파일 교체를, patch/Program.cs가 폴더 선택 UI를 담당합니다. scripts/build-patch.ps1은 실행기를 컴파일하고 Windows에서 업데이트·백업/버전·저장/런타임 보존·체크섬 거부·오류 복원·다운그레이드 거부를 시험합니다. 전체 실행본과 패치는 GitHub Actions에서 만들어 릴리스 초안에 첨부합니다.

## v0.5.1 · 자동 설치본 검색 패치
패치 ZIP을 폴더 전체로 압축 해제하고 FantasyStoryPatch.exe를 실행합니다. 기록된 경로·실행 중인 게임·바로가기·패치 주변·다운로드·바탕화면·문서의 제한된 범위를 검색합니다. 정상 설치본이 하나면 자동 업데이트하고, 여러 개면 선택합니다. 다른 드라이브 등에서 찾지 못한 경우에만 게임 실행 파일을 한 번 선택하면 이후 기억합니다. 게임 실행 중에는 강제 종료하지 않고 저장·종료를 기다립니다. 전체 디스크를 무제한 검색하거나 인터넷에서 패치를 자동 다운로드하는 기능은 아닙니다.
설치본은 app.asar 내부 package.json으로 식별하며 Codex 파일이 고정 경로에 없다는 이유로 정상 게임을 거부하지 않습니다. 빠진 파일·다른 앱·손상된 파일은 원인을 나눠 표시합니다. 로그인과 게임 저장은 유지합니다.

## v0.6.0 · 배경과 전신 캐릭터 / 나무 의뢰 게시판
현실 지하철·승강장·대합실 배경과 투명 전신 캐릭터를 독립 레이어로 표시합니다. 배경이 바뀌어도 캐릭터 이미지와 인물은 유지됩니다. 여경·유이의 본편과 여경의 AI 이야기 테스트에 적용했습니다. 서하와 이름 미정 소꿉친구의 전신도 준비했으며 본편에 아직 등장하지 않는 인물을 자동으로 해금하지 않습니다. 여학생은 주름 없는 짧은 H라인 치마·수선한 슬림핏의 짧은 셔츠·운동화 기준입니다. 과거 원화·컷신·SD는 원본 기록으로 보존하며 이번에 모든 과거 컷을 다시 그린 것은 아닙니다.
의뢰 게시판은 나무판에 붙은 종이를 클릭하면 큰 의뢰서가 펼쳐지는 방식입니다. 의뢰 생성·기한·수락·자동 저장 규칙은 유지합니다. 개발용 생성/시간 이동 설정은 접어 둡니다. 이벤트 컷신은 기본 전신 장면과 별도로 버튼으로 볼 수 있습니다.
