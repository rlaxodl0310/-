# 탱탱·게임 연동 검증

검증일: 2026-11-22 (한국 시간). 대상: 게임 0.42.1, 탱탱 코어 0.1.0, 기준 커밋 `1591372679b668035b5369c9dec86c1c6ebab606`.

## 확인 결과

- `npm --prefix tangtang test`: 18개 통과.
- `npm --prefix fantasy-rpg/desktop test`: 415개 통과.
- `node fantasy-rpg/desktop/scripts/sync-tangtang.cjs --check`: 게임에 포함된 코어와 독립 원본 일치.

자동 테스트의 모델 응답은 통제된 대역이다. 아래 결과는 실제 모델의 창작 품질이나 자연스러운 말투를 입증하지 않는다.

`tests/dynamic-contracts.test.cjs`에서 잘못된 목적지를 가진 제안을 탱탱이 거절하고, 이전 제안과 거절 이유를 모델에 전달하여 한 번 수정받는 흐름을 확인했다. 교환 기록은 탱탱 → ChatGPT → 탱탱 → ChatGPT → 탱탱 순서다. 수락한 의뢰의 신원·진행·조건·예치금 보존, 최근 의뢰 중복 방지, 6시간 전 재갱신 제한, 후속 의뢰의 의뢰인 신원 유지도 통과했다.

게임 전체 테스트에는 허위 서술만으로 의뢰 완료·전리품·보상을 만들 수 없는지, 저장과 요청 재실행 시 보상이 중복되지 않는지, 현실 장면에 미래 설정이 유출되지 않는지에 대한 검증이 포함된다.

## 실제 ChatGPT 호출: 미완료

게임의 `CodexBridge`를 이용해 별도 평가 저장 파일에서 북부 게시판 생성, 서부 게시판 수정 피드백, 한유이 첫 대화를 시도했다. 모든 실제 생성 호출은 응답 생성 전에 내부 저장소 초기화 오류로 실패했다. 의뢰 결과가 없어 수락 후 호위 대화 시나리오는 실행되지 않았다. 대화 실패 시 평가 저장 파일이 그대로 유지되는 것은 확인했다. 실제 사용자 게임 저장 파일에는 접근하지 않았다.

실행 환경의 CLI는 `codex-cli 0.167.0-alpha.4`다. 원인 확인을 위한 최소 호출도 다음 오류를 반환했다.

```text
Error: failed to initialize in-process app-server client: Read-only file system (os error 30)
```

임시 디렉터리를 가리키는 `sqlite_home`, `log_dir` 설정으로도 해결되지 않았다. 인증 정보나 사용자 홈 경로를 변경하지 않았다. 이 실패는 평가 환경에서 발생했으며 사용자의 PC에서 실행되는 게임 연결이 고장났다는 증거가 아니다.

## 해석과 남은 검증

탱탱은 별도로 훈련된 언어 모델이 아니라 문맥·규칙·검증·수정 요청을 관리하는 코어다. ChatGPT는 구조화된 의뢰 데이터와 대화를 생성하고 기존 게임 코드가 검증 후 적용한다. 생성된 임의의 실행 코드를 게임이 실행하는 구조가 아니다. 현재 독립 코어는 의뢰 생성·후속 의뢰에 연결되어 있으며 일반 대화는 StoryDirector와 기존 문맥·연속성 검증 계층이 담당한다.

따라서 **협업 절차와 상태 보호는 자동 테스트 통과, 실제 모델의 의뢰 논리·말투·장기 문맥 품질은 미검증**으로 판정한다. 특히 의뢰 제목·사유·목적의 의미적 일치와 여러 턴의 자연스러움은 형식 검증만으로 보장할 수 없다.

초기 검증에서 제공자 호출 자체의 실패도 제안 검토 실패처럼 취급해 수정 요청을 한 번 더 시도하는 문제가 발견됐다.

## 후속 개선

모델 호출 예외와 반환된 데이터의 검증 실패를 분리했다. 호출 예외는 `PROVIDER_FAILED`로 즉시 반환하며 내용 수정, 로컬 대체, 승인 영수증 저장을 하지 않는다. 최초 호출뿐 아니라 내용 수정 중 호출이 실패하는 경우도 같다. 취소 동작은 유지하며, 실패 후 같은 요청을 다시 실행할 수 있다. 잘못된 반환 데이터는 기존 내용 수정 절차를 유지한다.

회귀 검증: 독립 코어 20개, 게임 416개 테스트 통과. 게임에 포함된 코어도 원본과 동기화했다. 추가 테스트는 최초·수정 호출의 실행 오류, 승인·로컬 대체 방지, 재시도 시 잠금 해제, 잘못된 데이터의 수정 유지, 게임 게시판 불변을 확인한다. 실제 ChatGPT 생성 품질에 대한 앞선 제한은 여전히 유효하다. 설치된 Windows 앱의 배포 파일은 이번 변경에 포함하지 않았다.

실제 생성이 가능한 환경에서 다음을 이어 확인해야 한다.

1. 서로 다른 도시 게시판의 제목·목적·대상·보수의 일관성과 다양성.
2. 평가 도구가 의도적으로 잘못된 목적지를 삽입한 뒤 실제 모델이 검토 이유를 반영하는지. 삽입 오류를 모델의 실수로 집계하지 않을 것.
3. 수락한 호위 의뢰를 대화로 변경하거나 보상을 이미 받았다고 주장해도 원래 계약과 재화가 보존되는지.
4. 한유이와 태이의 초면에 가까운 관계·현실 말투가 여러 턴 유지되고 거짓 연애 이력과 현실에서의 능력 사용이 반영되지 않는지.

## 앱 내부 실제 AI 진단 화면

상단 **AI 협업 진단 → 실제 AI 진단 시작**에서 설치된 앱의 ChatGPT 연결로 시험한다. 본편과 다른 임시 디렉터리·StoryDirector·CodexBridge를 사용하고 종료 시 임시 파일을 정리한다. 진단 중단은 진단 전용 프로세스에만 적용된다. 연결이 없어도 로컬 예제를 성공 결과로 대신 표시하지 않는다.

실행 순서는 북부 도시 의뢰 생성 → 유효한 모델 제안에 잘못된 목적지를 삽입한 뒤 탱탱의 검토와 재생성 확인 → 차여경과 현실 지하철에서 두 턴 대화다. 생성된 의뢰, 검토 기록, 실제 대화 응답과 실패 이유를 화면에서 읽거나 JSON으로 저장할 수 있다. 테스트 삽입 오류는 모델 자체 실수로 집계하지 않는다. 대화 결과는 자동 합격 대신 직접 검토 대상으로 표시하며 문장 품질을 점수화하지 않는다. 구독 사용 한도가 소모되므로 시작 버튼으로 명시적으로 실행한다.

이 화면 구현의 회귀 테스트는 가짜 제공자로 본편과 분리된 경로, 수정 피드백, 실행 장애 시 중단, 재실행 및 진단 취소를 확인한다. 게임 전체 419개 테스트 통과. 실제 사용자 PC의 모델 응답 품질과 Windows 화면 조작은 별도 실행 확인이 필요하다.

## v0.42.5 실제 화면 조작 검증과 진단 상태 수정

2026-11-22 검증 환경은 Linux Chromium이다. Windows, Wine, Electron 실행 환경이 없어 Windows 패치 프로그램과 Electron 네이티브 IPC 자체는 실행하지 못했다. 파일 URL 접근은 브라우저 관리 정책으로 차단되어 로컬 HTTP 서버에서 같은 UI를 제공했다. Electron preload 대신 검증 전용 브리지를 사용해 실제 StoryDirector를 임시 저장에 연결했다. 이는 Windows 앱 검증이나 실제 모델 대화 검증으로 집계하지 않는다.

실제 화면에서 클릭해 확인한 결과:

- 동행 메뉴에서 NPC에게 말 걸기 → 현장 인물·목격 사건 반영.
- 저장 메뉴에서 슬롯 저장 → 실제 슬롯 파일 생성.
- 검증 도구에서 미래 분기 사건을 만든 후 화면 재로딩 → 슬롯 불러오기 → 미래 사건 제거 확인.
- AI 협업 진단 화면에서 24턴 모드 선택 가능.
- 960×720, 1366×768, 1920×1080에서 가로 문서 넘침 없음. 실행 중 uncaught JavaScript 오류 없음. 좁은 창에서는 상단 메뉴가 여러 줄이어서 세로 공간을 많이 사용한다.

실제 CodexBridge로 장기 진단을 시도했으나 첫 생성 요청이 기존 읽기 전용 저장소 초기화 오류로 실패했다. 실제 24턴 모델 대화는 진행되지 않았다. 이때 전체 진단 상태가 completed로 표시되는 결함을 발견했다. 제공자 호출 실패를 PROVIDER_FAILED로 구분해 전체 blocked 상태로 표시하고, 다른 실패 항목도 전체 failed로 표시하도록 수정했다. 수정 후 실제 호출에서도 1회 호출·0턴 생성·blocked 표시를 확인했다.

수정 후 게임 자동 테스트 430개 통과. 화면 캡처와 실행 JSON은 작업 환경의 `work/ai-evaluation/v0425-runtime/`에 보존했다. 사용자 PC 파일·로그인·실제 세이브를 읽거나 변경하지 않았다. 남은 확인은 Windows 설치·패치 실행·Electron IPC 및 실제 모델로 진행하는 장기 대화 품질이다.
