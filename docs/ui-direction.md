# 기본 UI 방향성 시안

상태: 화면 전환 중심으로 수정한 기획. 실제 Unity 실행 화면이나 구현 완료를 뜻하지 않는다.

![정면 캐릭터 중심 대화 화면](assets/dialogue-ui-preview.png)

## 핵심 규칙

한 번에 하나의 주요 화면만 표시한다. 탐색 위에 대화·일정·활동 카드·휴대폰을 동시에 겹쳐 놓지 않는다.
버튼이나 상호작용을 선택하면 해당 기능의 전용 화면으로 바뀐다. 뒤로 가면 이전 위치와 선택 상태로 복귀한다.

## 화면과 이동

| 현재 화면 | 입력 | 다음 화면 |
| --- | --- | --- |
| 캠퍼스 탐색 | 사람과 대화 | 대화 전용 화면 |
| 캠퍼스 탐색 | 장소 입장 | 해당 장소 화면 |
| 장소 화면 | 활동 선택 | 활동 상세·선택 화면 |
| 탐색·장소 화면 | 휴대폰 버튼 | 휴대폰 홈 화면 |
| 휴대폰 홈 | 일정·메시지·지도·일지 | 선택한 항목의 전용 화면 |
| 탐색·장소 화면 | 메뉴 버튼 | 상태·저장·불러오기·설정 메뉴 |
| 대화·활동 | 종료 또는 완료 | 결과를 반영하고 기존 장소로 복귀 |
| 저녁 캠퍼스·장소·활동 결과 | 하루 마무리 | 당일 활동 확인 후 다음 날 캠퍼스로 이동 |
| 3일차 저녁 | 3일의 기록 보기 | 플레이어의 활동 기록 확인. 추가 날짜는 없음 |

- 탐색: 작은 시간 표시, 휴대폰·메뉴 버튼, 장소 입장 안내만 표시한다. 현재 시제품은 캠퍼스 배경과 정면의 김태이 초상화를 사용한다. 실제 3D 공간 이동은 미구현이다.
- 대화: 배경과 2D 초상화, 이름, 대사, 선택지만 보여준다. 탐색 HUD와 휴대폰은 숨긴다.
- 대화 중 태이가 선택한 실제 대사를 상대의 답변 위에 표시한다. 상대가 되물으면 곧바로 그 질문에 대한 선택지를 보여주고, 매번 별도의 '이어가기' 버튼을 요구하지 않는다.
- 진행 중인 주제를 유지하며 '다른 이야기로 넘어가기'로 주제 선택에 돌아갈 수 있다. 대화 마치기는 장소 화면으로 복귀한다.
- 인물 구도: 등을 보이는 주인공 배경을 기본 화면에서 사용하지 않는다. 대화에서는 현재 발화하는 인물이 정면으로 보이며, 다인 대화는 발화 순서에 맞춰 인물을 전환한다.
- 행동 선택: 지금 가능한 활동과 시간 비용을 보여준다. 활동을 고르면 상세 화면에서 약속 충돌 등 알려진 결과를 확인하고 실행한다.
- 휴대폰: 아이콘을 선택해 일정·메시지·지도·일지로 이동한다. 화면을 겹쳐 띄우지 않는다.
- 상태: 체력과 피로 등의 상세 수치는 상태 화면에서 확인한다. 재난 중 즉각적인 위험은 최소한의 경고로 전달한다.
- 알림: 휴대폰 버튼의 작은 미확인 표시만 사용한다. 메시지 본문이나 다른 장소의 장면을 탐색 중 자동으로 띄우지 않는다.

현재 시제품은 날짜·요일·시간대를 상단에 표시하며 자유관·도서관·카페로 장소를 전환한다. 각 장소는 생활 묘사와 이동 동선으로 표현하며 실제 해당 시간에 있는 인물의 장면만 발생한다.
휴대폰 일정에서 다음 날 약속과 취소 버튼을 확인한다. 충돌하는 활동의 상세 화면에는 관련 인물과 약속을 명시한다.

장소 화면에 인물 카드나 '누구와 대화하기' 버튼을 배치하지 않는다. 장소에 도착하면 진행 중인 상황을 보여주고, 그 상황에서 할 행동을 선택한다.
같은 봉사단 인물의 이름은 처음부터 알 수 있지만 선택지는 '영수증을 건넨다', '빈자리를 물어본다', '하던 일을 계속한다'처럼 표현한다.
인물과 관련 없는 이동 선택은 게시판·공용 테이블·창가·휴게공간 등 공간을 기준으로 표시한다. 같은 동선이라도 날짜·시간·인물 일정·이전 선택에 따라 만남이 달라진다.
대화가 끝나면 인물 선택 목록으로 돌아가지 않고 주변 공간으로 돌아간다. 약속 없이 만난 사람이 계속 플레이어를 기다리는 구도를 반복하지 않는다.

![복도를 지나던 중 마주치는 장면](assets/identity-first-encounter.png)

![대화 상대 대신 이동 동선을 고르는 화면](assets/identity-after-encounters.png)

메뉴 화면 전환·뒤로 가기는 시간을 소모하지 않는다. 모든 날짜에 장소 이동·내부 탐색·짧은 현장 행동·대화 마무리는 여러 행동을 묶어 시간을 진행한다.
일정 기반 초기 시제품에서는 메뉴를 보는 동안 세계 시간을 정지한다. 실시간 탐색 도입 시 재검토한다.
활동 취소 시 결과를 적용하지 않는다. 완료된 활동의 시간·물자·관계 결과는 한 번만 반영한다.

## 정보 경계

지도는 알고 있는 장소만, 메시지는 실제 받은 내용만 보여준다. 타인의 모든 위치나 숨은 관계 수치는 공개하지 않는다.
UI를 전환해도 다른 인물의 일정과 사건을 계산하는 세계 상태는 유지한다. 화면을 열어야만 해당 장소의 사건이 진행되는 구조로 만들지 않는다.

## 미술 방향

크림색·짙은 남색 바탕에 청록색을 강조색으로 사용한다. 색과 함께 텍스트·아이콘으로 의미를 전달한다.
일상과 재난에서 기본 조작 위치를 유지하고 배경·조명·경고 우선순위로 분위기를 바꾼다.
캐릭터 초상화와 3D 외형의 주요 특징을 맞춘다. 시안의 시간·건물·외형은 참고용이며 확정 설정을 대체하지 않는다.

김태이의 헤어는 기존 히피펌 설정에서 수정한다. 일본 애니메이션 남자 주인공 같은 검은색 레이어드 헤어로, 강한 곱슬 대신 자연스러운 모발 흐름과 가벼운 볼륨, 층진 머리끝을 사용한다. 최신 탐색 시안에 이 방향을 반영했다. 정면 앞머리의 정확한 형태는 추후 캐릭터 시트에서 결정한다. 김태이의 얼굴은 진하고 강한 인상보다 예쁘장하고 섬세한 미남으로 잡는다. 얼굴 윤곽·눈매·눈썹의 강한 음영과 각을 줄이고 부드러운 인상을 유지한다. 차여경은 어깨 안팎의 중단발에 적당한 히피펌을 적용한다. 복슬한 느낌은 남기되 길게 늘어지는 머리, 과한 잔컬과 부풀린 볼륨은 줄인다. Unity의 투명 인물 아틀라스는 이 방향을 세 가지 표정 모두에 반영한다.

## 구현 시 확인

- 한 번에 하나의 주요 화면만 활성화되는가.
- 뒤로 가기 후 탐색 위치와 이전 메뉴 선택 상태가 복구되는가.
- 메뉴 탐색과 취소로 시간이 흐르거나 활동 보상이 발생하지 않는가.
- 시간 비용과 알려진 약속 충돌이 실행 전에 전달되는가.
- 본 적 없는 사건 정보가 노출되지 않는가.
- 키보드와 마우스로 같은 화면 이동이 가능하고 글자 크기를 조절할 수 있는가.

prototype/ 웹 시제품에서 전용 화면 전환, 활동 취소, 휴대폰 복귀, 세이브 슬롯 흐름을 구현하고 Chromium으로 검증했다. 정적 배경을 사용하는 기능 검증 단계이며 실제 3D 탐색·Unity UI 구현은 아직이다.
현재는 김태이·한서연·차여경·박소율의 정면 2D 초상화도 적용했다. 초상화는 외형 방향을 확인하는 초안으로, 표정별 차분과 최종 캐릭터 시트는 미완성이다. Unity UI 구현과 실제 3D 이동은 여전히 미구현이다.

## 이벤트에 따른 화면 반응

활동 상세 화면에서 상황에 맞는 참여 방식을 고른다. 선택된 항목은 테두리와 상태로 표시하며, 어떤 숨은 관계 수치가 오를지는 미리 숫자로 안내하지 않는다.
메시지·장소에서 이미 알게 된 내용만 지문에 반영한다. 조건부 부탁이 와도 별도의 인물 선택 카드나 대기 목록을 추가하지 않는다.
사건 분류명이나 내부 조건식은 개발 구조이며 실제 플레이 화면의 메뉴 이름으로 노출하지 않는다.

### 정보·획득 피드백

행동으로 새 정보를 알게 되면 화면 상단의 독립된 줄에 `◇ 새 정보`를 청록색으로 표시한다. 실제 소지 수량이 늘어난 아이템은 `▣ 아이템 획득`과 금색, 획득 수량으로 구분한다. 색상 외에도 기호와 문구를 함께 사용하며, 자동으로 사라지지 않고 확인 버튼으로 닫는다. 장면의 버튼을 가리는 오버레이는 사용하지 않는다.
알림의 `정보 · 소지품 확인` 또는 휴대폰의 `알게 된 정보 · 소지품`에서 정보 목록과 소지품을 확인한다. 정보에는 확인 날짜·장소·선택한 행동을 함께 기록한다. 본문에서 이미 알고 있는 정보의 정확한 명칭이 등장하면 청록색으로 강조한다. 재관찰이나 저장 불러오기로 신규 획득 알림을 반복하지 않는다.
현재 자유관의 공용 우산 대여가 첫 실제 아이템 지급 사례다. 보관 위치 발견은 정보이며 아이템 소유로 처리하지 않는다. 실제 대여 시 금색 획득 알림과 소지품 수량을 갱신하고, 반납 시 제거한다.

모든 날짜에 상단 시각을 표시한다. 짧은 이동·탐색·대화는 여러 행동을 묶어 시간이 흐르고 대화 도중에는 넘기지 않는다. 긴 활동 상세에는 현재 시각 기준 소요 시간과 종료 예상 시각을 표시한다. 16:00 대기나 한 활동 뒤 자동 귀가는 없으며, 저녁에도 가능한 자유행동을 이어간다. 귀가는 확인 화면에서 직접 결정한다.


### 동아리와 약속

휴대폰 학내 커뮤니티에서 모집글을 읽고, 이후 `읽어둔 동아리 안내`에서 공개 안내와 가입 상태를 다시 확인한다. 가입 버튼은 소속을 바꾸고, 실제 참석은 별도 제안으로 안내한다. 새 게임에는 가입한 동아리와 미리 아는 부원 이름이 없다.
일정 화면은 응답 전 제안과 참석 예정·처리 결과를 함께 보여준다. 누가 제안했는지, 날짜·시간대·장소 또는 활동, 겹칠 수 있는 일정, 수락·거절·사전 취소 버튼을 제공한다. NPC가 먼저 보낸 제안은 메시지와 화면 상단의 바로가기에서 확인한다. 제안과 수락된 약속을 같은 상태로 표시하지 않는다.
개인 약속도 인물 선택 메뉴를 생성하지 않는다. 실제 장소에서 자기 일을 하는 인물과 마주쳤을 때 오늘 약속을 기억하는 문장과 인사 선택지로 이어진다. 장소 입장만으로 약속을 지켰다고 처리하지 않는다.

### 전해 들은 이야기 표시

실제 만남에서 상대가 다른 사람에게 들은 내용을 꺼내면 기존 대화와 구분되는 `전해 들은 이야기` 문단을 보여준다. 인물은 전달자를 직접 언급하고, 확신할 수 없는 사정은 물어본다. 숨겨진 NPC 정보 교환을 알림으로 미리 공개하지 않는다. 태이가 그 이야기를 들은 시점에 정보 목록과 일지에 전달 경위를 남긴다. 일정에서는 NPC가 미수락 제안을 거둔 경우 `상대가 제안 보류`로 표시하고, 수락된 약속의 취소와 구분한다.


### 날씨와 예보

화면 상단의 작은 버튼에 날씨 기호·이름·기온을 함께 표시한다. 눌러 현재 장면을 대체하는 예보 화면을 열고, 뒤로 가면 진행 중이던 만남이나 대화로 돌아온다. 휴대폰에서도 같은 예보를 열 수 있다. 새 오버레이를 겹치지 않는다.
예보 화면에서 다음 날씨와 우산 준비를 확인한다. 자유관에서는 대여·반납 버튼을 제공하며 실제 아이템 획득은 기존 금색 알림으로 보여준다. 활동 카드와 상세에는 우천 대체·시간 변화·강한 비의 제한을 실행 전에 안내한다. 날씨 때문에 취소된 약속은 개인 불이행과 구분한다.
캠퍼스는 기존 배경 위 밝기·정적인 빗줄기 표현을 사용한다. 현재 실제 3D 날씨 렌더링은 아니다. [강한 비 예시의 모바일 화면](assets/weather-ui-preview.png)은 개발용 비교 모드에서 캡처했다.

### 일상 속 작은 변화

3일차 장소의 기존 이동 선택에 뒤편 출입문·도서관 로비 안내·창밖 정류장을 추가한다. 해당 공간을 살펴본 뒤 별도 전체 화면에서 더 확인하거나 돌아갈 수 있다. 새 인물 대기 목록이나 중첩된 이벤트 창을 만들지 않는다. 보이는 내용은 새 정보 알림으로, 추가 확인 결과는 안내와 일지로 남긴다.
접한 일이 생기면 휴대폰에 `확인한 일`을 표시한다. 직접 목격·안내 확인·전해 들음을 구분하고 출처와 내용을 함께 보여준다. 감염 확정 표시나 위험도 수치, 전지적인 사건 목록은 제공하지 않는다. 기존 일상 활동과 `교내 안내 확인`을 같은 활동 화면에서 비교하며, 다른 활동을 택해 놓칠 약속은 기존 방식으로 경고한다.
[출입문 앞에서 안내를 확인하는 모바일 화면](assets/campus-warning-preview.png)은 실제 시제품 캡처다.

### NPC의 판단과 동행

기존 대화에서 `주변에서 접한 일 이야기하기`를 누르면 태이가 실제로 아는 내용만 출처와 함께 고를 수 있다. 전달한 뒤에는 동행을 물어보거나 남은 대화로 돌아간다. 동행에 대한 답변 다음에는 일정 확인·활동 선택·대화 복귀를 제공하고, 앞서 하던 사진·길 안내 질문의 선택지를 바로 붙이지 않는다.
개인의 판단 점수를 노출하는 패널 대신 실제 장소에서 볼 수 있는 연락·정리 모습과 NPC가 보낸 연락으로 변화를 표현한다. 대화 중 이동 계획이 바뀌더라도 현재 교환을 마친 뒤 장소를 옮긴다. 동행 제안은 기존 일정 화면에서 응답하고, 실제 활동 결과에 함께한 인물을 표시한다.
[동행을 수락한 뒤의 모바일 대화 화면](assets/risk-decision-preview.png)은 실제 시제품 캡처다.

### 장면에서 생겨나는 행동

첫 화면은 오전 등교와 임박한 수업·장소를 우선 보여준다. 공강에는 자유관·도서관·카페 등으로 가는 동선을 제공한다. 커뮤니티 알림을 이야기 선택지로 강제하지 않는다. 실제 장소에서 만난 사람과 보거나 들은 요소가 후속 선택의 근거다.
행동은 현재 장소·날짜·이미 읽거나 본 정보·교류·약속에 따라 달라진다. 동아리 안내는 커뮤니티의 해당 모집글을 읽은 뒤 열리고, 준비를 도울지 살펴보면 바로 해당 일의 설명·소요 시간·약속 충돌로 이어진다. 취소는 공통 분류 화면이 아니라 직전 상황으로 돌아간다. 읽어둔 기록과 일정은 휴대폰에서 보조적으로 확인한다.
[공강 중 자유롭게 장소를 고르는 모바일 화면](assets/scene-flow-preview.png)은 실제 시제품 캡처다. 장소 안에서는 상황과 교류에 따라 후속 선택이 생긴다.


### 휴대폰의 학내 커뮤니티

휴대폰 홈에서 학내 커뮤니티를 누르면 캠퍼스톡을 휴대폰 안의 한 화면으로 연다. 전체·자유·모집·공지 탭, 글 목록, 작성자 구분, 본문, 익명 댓글과 글쓴이 답글, 공감을 제공한다. 모집글은 해당 동아리 안내와 현장 방문으로 연결한다. 커뮤니티 안에서는 행동 시간 설명과 다른 약속 제안 띠를 숨겨 읽는 화면에 집중한다.
새 글이 생겨도 목록을 밀어 올리지 않고 도착 알림으로 갱신한다. 본문을 읽는 동안에는 새 댓글 도착을 확인하게 하고 본문은 유지한다. 익명 글에는 신원·내용 미확인임을 표시하고, 실제 공지와 운영진 모집글은 출처를 구분한다. 확인되지 않은 이야기를 확정된 사건처럼 강조하지 않는다.
[가상 학생들의 글과 댓글이 쌓인 모바일 화면](assets/community-feed-preview.png)은 실제 시제품 캡처다. 외부 AI나 실제 에타 계정에 연결하지 않는 게임 내부 커뮤니티다.

### 자유행동과 실제 약속

일정에는 실제로 받은 제안·수락한 약속·처리 결과와 완료한 활동만 표시한다. 합주나 음악 작업을 개인 시간표에 자동 배치하지 않는다. 커뮤니티는 휴대폰에서 직접 열며, 탐색 장면에서 커뮤니티 열람을 다음 할 일로 제시하지 않는다. 기존에 수락한 약속은 자유행동 중에도 유지되며, 다른 일을 한 번 했다는 이유로 즉시 불이행 처리하지 않는다.

### 도서관의 생활 행동

도서관 안에 독서·코딩 공부·로비 휴식 선택을 추가한다. 결과는 같은 장소의 본문 안내로 보여주고 별도 중첩 창을 열지 않는다. 실제 확인한 서가·노트북 좌석·로비 벤치 위치는 기존 정보 강조와 휴대폰 정보 목록에 연결한다. 현재 시각과 장소 분위기, 현장 동선, 기존 긴 활동과 이동 선택은 유지한다. 짧은 행동으로 일정이나 약속을 자동 등록하지 않는다.

### 학교 건물과 층별 공간 안내

주요 건물은 본부동·예술동·음악관·체육관·외식관·창조관·은혜관·자유관·조형관·백석홀의 10곳으로 표시한다. 휴대폰 지도에서 주요 건물 목록과 창조관 내부 도서관·대학가 카페·명칭 미정인 기숙사 방문 공간을 구분한다. 화면의 현재 위치와 직접 알아둔 정보는 유지한다.

각 건물의 `건물 안의 다른 공간으로 간다`를 누르면 해당 건물의 내부 안내 화면으로 전환한다. 층수가 확정된 시설만 `4층 구석 · 대형 합주실`처럼 표시하고, 나머지는 시설명만 보여준다. 예술동 7층에는 강의실과 연습실이 함께 있으며 두 용도를 지우거나 하나로 합치지 않는다. 공간을 선택하면 장소 화면에 그 공간의 관찰 내용을 보여준다. 지도와 안내를 읽는 것만으로 내부 발견 기록을 미리 지급하지 않는다.

창조관 도서관은 기존 도서관 화면으로 이어진다. 외식관 안 카페와 대학가 카페를 같은 위치로 취급하지 않는다. 사용자에게 설정용 ID를 노출하지 않는다. 은행·편의점은 이번 단계에서 위치 확인만 가능하며 실제 거래 메뉴처럼 표시하지 않는다.

### 시간표·수업·공강

새 게임은 오전 09:00 등교에서 시작한다. 임박한 수업이 있으면 기존 배경·정면 초상화·장면 패널 안에서 과목·시각·건물을 안내하고 수업 장소 이동을 우선한다. 건물 화면의 수업 안내에서 올바른 내부 공간으로 이동한 뒤 입실을 선택한다. 수업은 과목별 전용 화면에서 참여 방식을 고르며, 마친 뒤 실제 종료 시각과 수업 결과를 표시한다. 시간표와 수업 창을 다른 화면 위에 겹쳐 띄우지 않는다.

휴대폰에 `시간표 · 출석`을 추가한다. 플레이어의 3일 수업·시간·장소와 예정·출석·지각·일부 참석·결석·이전 저장 기록 없음 상태를 보여준다. 다른 인물의 시간표와 위치를 명단으로 노출하지 않는다. 개인·동아리 약속 화면은 기존 기능을 유지하며 수업 표와 구분한다. 시간표를 확인하는 것만으로 출석 처리하지 않는다.

장소에는 다음 수업 안내를 두고, 공강이면 자유행동을 이어간다. 긴 활동이 수업과 겹치면 과목·시각과 지각·결석 가능성을 상세 화면에 표시하고 실행 버튼에도 충돌을 드러낸다. 일찍 귀가하는 확인 화면도 남은 수업이 결석 처리됨을 안내한다. 하루 마무리에는 실제 수업 출석을 포함한다. 오전은 시각에 맞춰 오전으로 표시한다.

### 미연시 방식의 문장·선택 진행과 상단 메뉴

현재 진행 화면은 배경과 정면 인물을 크게 유지하고 하단의 단일 대화창을 사용한다. 종전의 긴 본문·학교 안내·여러 행동 목록을 한 번에 세로로 나열하는 화면을 대체한다. 장소·수업·활동 상세·결과·만남·실제 대화·건물 내부 안내·하루 정리를 이 흐름으로 연결한다. 메뉴·휴대폰은 전용 화면으로 전환하며 여러 창을 겹쳐 열지 않는다.

설명과 대사는 약 180자 이내의 읽기 단위로 나눈다. 문장을 자르거나 생략하지 않으며 끝까지 읽은 뒤 선택 단계로 넘어간다. `다음`, 문장 터치, 스페이스를 지원한다. 선택지가 나온 뒤에는 문장을 다시 눌러도 임의로 답을 고르지 않는다. 실제 대화에서는 내 선택 대사 → 관찰 가능한 반응 → 상대의 답변을 구분해 표시한다. 인물 이름은 기존 인지 규칙을 따른다.

선택은 한 번에 최대 3개 버튼으로 보여준다. 선택이 많을 때는 실제 행동 두 개와 다른 선택을 보는 버튼 하나를 표시하며, 페이지 순서를 작게 안내한다. 모든 기존 선택은 뒤의 묶음에서 다시 찾을 수 있고 넘기는 동작은 행동·시간·관계 보상에 집계하지 않는다. 대화의 주제를 바꾸거나 약속을 물을 때는 `조금 다른 이야기를 꺼낸다` 다음 단계로 묶고, 다시 원래 답변 선택으로 돌아올 수 있다. 활동의 참여 방식도 별도 선택 단계 뒤 실행 여부를 확인한다.

우측 상단에는 휴대폰과 메뉴 버튼을 둔다. 메뉴의 기능 탭에는 이동·시간표·약속·지도·정보·메시지·일지·날씨를, 저장·설정 탭에는 저장·불러오기와 비교 예시를 둔다. 수업이 임박했을 때의 실제 입실·수업 장소 이동은 이야기 선택에도 유지한다. 일반 장소 간 이동과 기록 메뉴를 장면 답변에 모두 섞어 나열하지 않는다. 새로운 약속 제안은 메뉴 표시에 작게 알린다.

새 정보는 작은 획득 표시와 정보 보기로 안내하며 목록을 대화창에 전부 펼치지 않는다. 실제로 경과한 시간은 다음 이야기 문장으로 알리고 현재 시각과 날씨도 상단 장면 정보에 유지한다. 메뉴·휴대폰·커뮤니티·모집 안내를 거쳐 돌아와도 원래 문장과 선택 단계가 유지된다. 이 화면 커서는 현재 실행 중에 유지하며 저장 파일의 세계 상태와 구분한다.

밝은 대화창과 짙은 글씨를 사용하고, 정보는 짙은 청록·아이템은 짙은 황갈색으로 구분한다. 모바일에서는 인물 얼굴과 하단 대화창이 함께 보이도록 배치하고 대화창만 필요할 때 내부 스크롤한다. PC도 같은 화면 구성을 사용한다. 건물마다 새로운 내부 일러스트를 추가한 것은 아니다.

### 커뮤니티 모집글에서 실제 작업으로

봉사·음악·축구 모집글에 공개 활동 상세 선택을 둔다. 동아리 가입 안내와 구분하고, 상세에서 날짜·장소·총 소요 시간·참여 가능 여부를 읽은 뒤 현장으로 간다. 상세를 읽기만 했는데 이미 현장 인물과 만난 것처럼 서술하지 않는다. 불참·미가입도 가능하다.

현장에서는 기존 미연시 대화창과 3개 이하의 선택을 유지한다. 작업을 고르면 내 행동과 현장 반응이 차례로 나오고 다음 단계로 이어진다. 상단에 활동 이름과 1/3~3/3 진행을 표시한다. 현장 인물은 실제 소개 전에는 이름을 숨긴다. 진행을 잠시 멈추는 선택과 메뉴의 이어 하기에서 단계가 보존되며 이동·시간표 등 기능 버튼을 매번 본문에 나열하지 않는다.

마지막 단계 뒤에는 실제로 한 일의 결과와 참여 시간을 보여준다. 가입 안내를 읽거나 현장을 떠나는 선택은 별도다. [봉사 물품 준비 진행 화면](assets/community-activity-preview.png)은 실제 실행 화면이다. `community_activities_browser_smoke.py`는 모집글에서 시작하는 세 활동, 중단·저장·재개와 우천 대체를 현재 대화 UI에서 검증한다.

대화 재방문은 인물 선택 메뉴가 아닌 현장 조우를 유지한다. 완료한 대화의 후속 조건이 생기면 이전과 다른 행동 중인 인물을 마주치고, 앞선 이야기의 결과를 묻는 말로 이어진다. 선택은 실제 말투의 문장으로 표시하며 기존 한 문장씩 읽기·세 개 이하 선택지 UI를 유지한다. 현재 세 인물별 두 차례 후속을 제공하며 준비된 내용이 없으면 같은 사건을 재시작하지 않는다.

NPC의 피로·부담·대화 여유는 숫자 게이지나 속마음 설명 대신 시계 확인, 대답 간격, 작업을 놓지 못하는 손동작과 직접 발언으로 표현한다. 수업 직전에는 짧은 인사와 다음으로 미루기가 중심이 되고, 편안할 때만 원래 주제로 이어가는 선택을 제공한다. 상황 확인과 원래 대화는 한 화면의 미연시 흐름으로 이어지며 별도의 상태 팝업을 띄우지 않는다. 거절 뒤의 재촉은 관계와 현재 기분에 영향을 남긴다.

일반 플레이의 평상시 일대일 대화는 생성한 발언과 그에 맞는 두 후속 발언, 대화 마치기 선택으로 표시한다. 같은 상황의 새 대화에서도 발언은 달라질 수 있지만 읽는 도중·메뉴 왕복·저장 복원 중에는 바뀌지 않는다. 기존 미연시의 문장별 읽기와 세 개 이하 선택지를 유지하고 생성 과정이나 난수 값은 플레이 화면에 노출하지 않는다.

자체 모델은 게임 서버가 준비되면 자동 사용하며 플레이어용 AI 설정·모델 다운로드 화면을 추가하지 않는다. 새 발화를 기다릴 때만 ‘잠시 말을 고르고 있다…’와 ‘기다리지 않고 이어가기’를 표시한다. 대기 중에는 시간 진행·중복 답변·키보드 넘기기를 막고, 실패하면 기존 발화를 보여주어 계속 플레이할 수 있게 한다.


호실 안내는 층 선택 → 해당 층 호실 선택 → 방 앞 장면 전환 순서로 제공한다. 시간표·도착 안내·장면 위치에 401호 같은 정확한 주소를 표시한다. 건물 진입에서 학과 구성 설명을 반복하지 않는다. 휴대폰의 동아리 안내는 신청서를 여는 기능이며 원격 즉시 가입 버튼을 없앴다. 현장 면접과 결과 연락 뒤 가입 의사를 확인한다. ‘알게 된 사람들’은 배운 이름·전공·마지막 목격만 보여주고 미대면 인물의 프로필이나 현재 위치를 공개하지 않는다.

### 메뉴와 휴대폰의 탐색성 개선

메뉴는 ‘지금 할 일·학교생활·내 기록’으로 묶고 이동과 휴대폰을 큰 바로가기로 배치한다. PC에서는 현재 인물·위치·시각을 왼쪽 요약에, 기능을 오른쪽에 놓는다. 모바일에서는 요약을 짧은 가로 카드로 바꾸고 기능을 두 열로 배치한다. 아이콘과 기능명, 짧은 용도 설명을 함께 사용하고 색만으로 기능을 구분하지 않는다. 상단 미연시 메뉴에도 휴대폰/메뉴 아이콘을 추가했다.

휴대폰은 독립된 홈 화면으로 바꾸고 현재 게임 시각·요일·현재 위치, 다음/진행 중 수업과 실제 호실, 날씨 위젯, 3열 앱 아이콘을 제공한다. 캠퍼스 앱과 개인 기록 앱을 구분한다. 메시지는 실제 미열람 메시지 수, 일정은 응답 전 제안 수만 배지로 표시한다. 메시지를 읽으면 배지가 사라진다. 허구의 신호·배터리 수치나 플레이어가 모르는 인물 정보는 추가하지 않는다. 학과 소개·AI 설정 같은 구현 설명을 새 홈 화면에 넣지 않는다.

저장 탭은 슬롯별 게임 날짜·시각·장소를 미리 보여주고 빈 슬롯 불러오기는 비활성화한다. 관계·날씨의 개발용 비교 설정은 접힌 영역에 두어 일반 저장 동선과 구분한다. 메뉴·휴대폰 상단에 중복되던 공통 날씨 막대는 숨기고 각 화면의 위젯/기능으로 접근한다. 메뉴·휴대폰을 열고 닫는 행위나 앱 사이 이동은 게임 시간을 진행하지 않는다. 기존 대화 문장과 선택지 커서는 왕복 후 유지한다.

검증: 기존 자동 테스트 220개 통과. 웹 모듈·단독 HTML의 320/390/1440px 화면에서 가로 넘침, 앱 접근, 빈 슬롯·저장 정보·불러오기, 미열람 배지와 읽기 후 제거, 대화 복귀를 브라우저로 확인했다. 별도 단위 테스트로 스타일 구현을 복제하지 않고 실제 화면 검증을 사용한다. 실행 화면은 `docs/assets/phone-home-ui.png`, `docs/assets/menu-dashboard-ui.png`에 저장한다.

### 비 오는 점심 동행 장면

건물 출입구의 우연한 마주침에서 바로 기존 미연시 화면으로 이어진다. 이름을 모르면 외형 설명을 유지하고, 실제 자기소개 후에만 이름표를 바꾼다. 동행 제안·길 고르기·걷는 동안의 행동·자리 찾기·헤어짐이 같은 흐름 안에서 이어진다. 대화는 플레이어 발언/행동 → 상대 반응 → 이동이나 식사가 진행된 묘사 순으로 읽는다. 걸어 도착하면 장면 위치가 외식관 1층 101호로 바뀌며 강제로 다른 메뉴를 띄우지 않는다. 대화와 선택은 기존 세 개 이하 선택지 규칙을 따른다. 메뉴·휴대폰 왕복과 저장 복원으로 현재 문장이 바뀌지 않고 메뉴에서 진행 중인 장면으로 돌아올 수 있다. 실행 예시는 `docs/assets/rain-lunch-preview.png`에 저장한다.

### 합주 활동 장면

기존 초상화 대신 합주실·마이크·악기·함께 연주하는 세 사람을 같은 미연시 화면에 배치하는 원본 SVG 2D 시제품을 추가했다. 태이는 파트 선택에 따라 마이크/베이스/기타를 들고, 준비·파트 연습·호흡 맞추기·공연·마무리 상태를 표시한다. 공연에는 작은 자세 움직임을 적용하고 동작 줄이기 설정을 따른다. 메뉴 오버레이를 추가하지 않으며 이전 미연시 읽기와 선택지 흐름을 유지한다. 3D 모델이나 최종 캐릭터 일러스트는 아니고 연출 구도 검토용이다. 음원 재생도 아직 없다. 실행 장면은 `docs/assets/music-activity-preview.png`에 저장한다.

검증: 전체 JS 테스트 233개 통과. `python3 prototype/music_scene_browser_smoke.py`로 웹/다운로드 HTML에서 수업 → 휴대폰 모집글 → 실제 합주 → 저장/불러오기 → 공연, 파트·단계 그림 전환과 시간, 모바일 가로 넘침을 확인했다. 기존 세 공개 활동 브라우저 회귀 검증도 수행한다.

### 농구·조리·운반 활동 화면

공통 미연시 화면 안에서 준비/활동/마무리/완료에 맞춰 코트와 골대·공, 앞치마와 조리대·냄비, 운반 상자·통로 장애물·보관대를 표시한다. 태이의 슛/패스/운반 자세와 도구 위치가 실제 선택에 따라 바뀐다. 농구 장면에는 실제 공격 횟수와 득점, 선택 직전 문장에는 관찰한 수비와 남은 여력을 표시한다. 한 번에 기존 규칙의 최대 세 선택지를 유지하고 읽기·메뉴 동작으로 활동 결과를 바꾸지 않는다. 조리의 수증기 움직임은 동작 줄이기 설정을 따른다. 모바일에서는 전체 코트가 보이도록 장면 비율을 보존한다.

캠퍼스톡에 ‘체험’ 탭을 추가하고 동아리 모집과 구분한다. 체험 게시물의 진행자 명칭을 표시하며 없는 동아리 가입 안내 버튼을 만들지 않는다. 정확한 활동 호실에서는 상황형 참여 선택지가 나타나 휴대폰을 읽지 않아도 현장 안내를 듣고 시작할 수 있다. 읽지 않은 게시글을 읽음 처리하지 않으며 돌아가기 동선도 현장에 연결한다.

검증: JS 전체 240개 통과. 웹 모듈과 단독 HTML에서 실제 수업→체험글→농구(공격 중 저장/불러오기)→조리→직접 호실에 들어가 운반에 참여하는 흐름을 Chromium으로 검증했다. 활동 시간·부분 저장·완료·가로 넘침·미열람 게시글 지식 경계를 확인했고 기존 세 공개 활동 브라우저 회귀 검증도 통과했다. 예시는 `docs/assets/basketball-activity-preview.png`, `docs/assets/cooking-activity-preview.png`, `docs/assets/carry-activity-preview.png`에 저장한다.

### 활동 중 짧은 직접 조작

액티비티의 행동 선택 후 기존 하단 이야기 패널이 가벼운 미니게임 패널로 바뀐다. 장면과 상단 메뉴는 유지하며 모달을 겹치지 않는다. 제목·입력 횟수·짧은 조작 안내·목표 구간·이동 표시·큰 조작 버튼·즉시 피드백을 제공한다. 시작과 조작은 Space/클릭/터치를 함께 지원한다. 목표는 색 외에도 테두리와 ‘목표’ 문구로 구분한다. 매 프레임 보조기기에 위치를 읽어주지 않고 입력 후 정확도만 상태 안내로 읽는다. 타이밍 없이 진행하는 버튼도 제공한다.

미니게임 중 Space가 이야기 넘기기로 동시에 처리되지 않는다. 길게 누르거나 빠르게 중복 클릭해도 연속 입력으로 완료되지 않는다. 메뉴 버튼에 키보드 포커스가 있으면 기본 버튼 조작을 유지한다. 결과는 확인 버튼으로 명시적으로 넘긴 뒤 기존 대화·활동 화면으로 돌아간다. 모바일에서는 큰 조작 버튼을 한 줄로 배치하고 작은 화면은 패널 내부에서 스크롤한다.

검증: 전체 JS 테스트 247개 통과. `python3 prototype/activity_minigame_browser_smoke.py`에서 웹/단독 HTML의 실제 Space·마우스·터치, 키 유지 중 반복 억제, 확인 전 무보상, 메뉴 중 정지, 1회 입력 후 저장/불러오기, 정확도에 따른 결과와 소요 시간을 확인했다. 기존 액티비티 브라우저 검증은 보조 진행 경로도 확인하도록 갱신했다. 일반 미연시 화면 브라우저 회귀 검증도 수행한다. 미리보기는 `docs/assets/activity-minigame-preview.png`, `docs/assets/activity-minigame-mobile.png`다.

### 캐릭터 일러스트·표정·자세 개선

`docs/assets/activity-character-scenes.png`는 태이의 농구/조리/운반 3열 활동 CG이고, `docs/assets/character-expressions.png`는 태이·서연·여경·소율 순서의 4열 × 미소/걱정/진지함 3행 아틀라스다. 원래 얼굴과 의상을 참조해 생성했다. 활동 화면은 단순 벡터 인물 대신 중앙 CG와 같은 이미지의 흐린 주변 배경으로 구성하며 모바일에서는 얼굴을 상단 위치 안내 아래에 배치한다. 그림을 다른 비율로 늘리지 않고 중앙 인물 비율을 유지한다. 기존 기본 초상화도 남겨 중립 장면과 새 연기 이미지를 구분한다.

대사 줄이 바뀔 때 현재 문장과 상태에 맞는 표정·자세를 적용하고 메뉴 왕복으로 재추첨하지 않는다. 이름을 모르면 기존 외형 이름표를 유지한다. 입력 미니게임에는 각 입력 점수 칸과 정확도별 짧은 소리를 붙이고 음소거 상태를 브라우저에 보존한다. 소리는 직접 입력할 때만 재생하며 외부 파일이나 음성 API는 사용하지 않는다. 운동장과 야외 코트는 별도 야외 배경을 사용한다.

검증: JS 250개 통과. `freedom_art_browser_smoke.py`로 웹/단독 HTML의 오전 야외 탐색·수업 중 자유행동·CG 표시, 실제 감정 상태 3종에 따른 대화 초상화와 메뉴 왕복 유지 여부를 확인한다. 미니게임 키보드/클릭/터치와 일반 미연시 화면도 기존 브라우저 검증을 수행한다.

### 전체 인터페이스 정리

`prototype/interface.css`에 공통 색상·테두리·여백·타이포 규칙을 모았다. 밝은 종이 바탕, 짙은 청록의 주요 동작, 옅은 녹색/금색 보조 강조를 이야기·메뉴·휴대폰·커뮤니티·이동·기록·저장·미니게임에 적용한다. 서버용 페이지와 다운로드 HTML은 동일한 스타일을 사용하고 단독 HTML에는 새 CSS까지 인라인으로 포함한다.

이야기 화면은 위치/호실/시간/날씨를 작은 HUD로 묶고 중복 건물 표기를 없앴다. 대사에 현재 문장/전체 문장의 실제 읽기 진행 표시를 제공하고 선택지에는 번호·간격·보조 선택 스타일을 적용한다. 캐릭터 이미지 가장자리와 종이 패널을 부드럽게 연결하고 중요한 이름·대사·주요 버튼의 대비를 유지한다. 모바일에서는 위치 안내와 상단 메뉴가 겹치지 않게 배치한다. 메뉴·휴대폰은 기존 기능/읽지 않은 알림/저장 동선을 유지하면서 색과 모서리·아이콘·헤더 규칙을 통일했다. 커뮤니티는 글 단위 카드, 기록과 시간표는 목록 카드로 구분한다.

캠퍼스 이동은 단순 건물 버튼 목록을 검색 가능한 장소 카드로 바꿨다. 전체/야외/강의·연습/생활·모임 분류, 장소/공간 검색, 현재 위치, 실제 결과 개수, 결과 없음 안내를 제공한다. 모바일 두 열·PC 세 열로 표시한다. 분류와 검색은 화면 상태만 바꾸며 게임 시간·발견 정보·인물 위치를 변경하지 않는다. 검색어 입력 중 포커스는 유지하고 휴대폰 왕복 후 조건도 유지한다. 장소명과 공용 공간의 기본 안내만 보여주고 NPC의 실시간 위치나 아직 배우지 않은 개인정보는 표시하지 않는다.

검증: 기존 JS 250개 통과. `interface_browser_smoke.py`는 웹/단독 HTML의 320/390/1440px에서 검색/분류/결과 없음·검색 포커스·휴대폰 왕복·시간 유지·HUD 간격·실제 열 개수를 확인한다. 단독 HTML을 웹으로 제공해 검증하고 CSS가 인라인임을 별도로 검사한다. 관리 브라우저는 file:// 접근을 금지하므로 이번 환경에서 파일 직접 열기 검증은 하지 못했다. 기존 미연시·메뉴/휴대폰·저장/알림·Space/마우스/터치 미니게임 브라우저 검증도 통과했다. 미리보기는 `docs/assets/interface-story-mobile.png`, `interface-menu-preview.png`, `interface-phone-preview.png`, `interface-travel-preview.png`다.

### 주문 행동과 우연한 상황의 연결

카페의 ‘주문대 쪽으로 간다’는 같은 미연시 화면에서 메뉴 → 온도 → 주문 확인 → 준비된 음료 수령 → 마시기/이동으로 이어진다. 선택 전에는 가격, 결제 전에는 실제 지출과 준비 대기를 안내한다. 수령 후에만 기존 획득 안내로 음료를 표시한다. 주문·활동·사건은 각각의 현재 문장과 소수의 선택지로 읽으며, 별도 고정 인물 대화 메뉴나 자동 합석을 추가하지 않는다.

일상 활동을 마쳤을 때 우연한 일이 생기면 진행한 활동과 눈앞의 사건을 이어 읽고 대응을 고른다. 메뉴/휴대폰 읽기는 결과를 바꾸지 않고 저장 후 메뉴 카드로 같은 사건에 돌아올 수 있다. 다른 행동을 택하고 떠나도 진행은 가능하다. 예시 화면은 `docs/assets/cafe-order-preview.png`, `docs/assets/everyday-event-preview.png`에 저장한다.

검증: JS 전체 256개 통과. 새 카페/일상 브라우저 검증은 웹/단독 HTML의 주문·지불·저장/복원·수령·소비, 우연한 일의 대응과 저장 복귀, 다음 활동의 묘사 변화, 초면의 거리감을 확인한다. 일반 미연시·공개 체험·Space/클릭/터치 미니게임 회귀 검증도 통과했다.

### 카페 기준 장면으로 미술 방향 재정리

카페 주문 장면을 완성도 기준 화면으로 다시 제작했다. `docs/assets/cafe-order-cinematic.png`는 기존 태이 얼굴과 운동복을 참조한 단일 와이드 CG다. 카운터·직원·창가·실내 조명·주인공을 같은 시점과 빛으로 구성하고, 주문 전 커피를 들고 있지 않게 했다. 주문 화면에서는 야외 캠퍼스 배경과 별도 초상화를 제거하고 이 CG 한 장을 원본 비율로 표시한다. PC는 공간 전체를, 모바일은 주인공·카운터가 남는 높이와 위치를 사용한다. 직원은 이름 미정의 배경 인물이다. 이 CG는 주문 이벤트의 정지 키아트이며 결제/수령 단계별 애니메이션이나 날씨별 신규 그림은 아직 없다.

공통 미연시 대사창은 종이 카드와 두꺼운 테두리 대신 어두운 반투명 패널·얇은 선·작은 이름표로 바꿨다. 선택지는 큰 둥근 버튼 대신 줄 간격과 얇은 구분선으로 정리하고 포커스 테두리와 실제 터치 영역은 유지했다. 상단 위치/메뉴도 작은 각진 표기로 통일했다. 미니게임은 PC에서 작은 하단 패널로, 모바일에서는 조작 버튼 크기를 유지한 간결한 패널로 구성한다. 기존 활동 CG의 주변을 늘려 흐리게 채우던 배경을 없애고 단색 여백을 사용한다. 메뉴·기록의 과도한 곡률과 그림자도 줄인다. 기존 모든 이벤트 일러스트를 새로 그린 상태는 아니며 카페를 먼저 기준 장면으로 반영했다.

검증: `cinematic_cafe_browser_smoke.py`로 웹/단독 HTML, 390px 모바일/1440px PC의 실제 CG 로딩·별도 초상화 미중복·선택지·주문/수령·가로 넘침을 확인했다. 기존 대화 대비/진행·Space/클릭/터치 미니게임·메뉴/휴대폰/저장 브라우저 검증도 통과했다. 실행 예시는 `docs/assets/cinematic-cafe-mobile.png`, `docs/assets/cinematic-cafe-desktop.png`다.

### 다인물 봉사 준비의 장면 흐름

현재 준비실에 있는 사람과 실제 들은 시간 제약을 단계별 설명에 표시한다. 이름을 모르면 외형 이름표로, 직접 소개를 나눈 뒤에만 이름으로 표시한다. 늦게 오는 사람은 다음 실제 교류 때 소개하고 먼저 간 사람을 계속 대화 초상화로 띄우지 않는다. ‘가능한 시간과 역할 듣기/도움 범위 다시 나누기/직접 마무리’ 선택을 기존 수량 대조/운반/인수인계와 함께 제공하며 한 화면 최대 선택지 규칙을 유지한다. 현장 참여와 커뮤니티 공개 체험이 같은 장면으로 이어진다.

대화 화면의 추가 행동에서 실제 참가자에게 ‘지난 봉사 준비가 어떻게 됐는지’ 물어볼 수 있다. 이름을 아직 모르거나 실제 참가하지 않은 사람에게는 이 행동을 만들지 않는다. 보고 후에는 출처와 범위를 저장하고 같은 보고를 반복 보상하지 않는다. 이번 변경은 사건 구조와 기존 캐릭터 초상화 연결이며 별도 단체 이벤트 CG를 새로 제작한 것은 아니다.

검증: 전체 JS 266개 통과. 참가/중도 이탈/늦은 합류, 같은 조의 공동 책임과 단독 부담, 고호감도의 도움 거절, 비참여 세계 진행과 관계 변화, 타 일정 우선, 저장·읽기 무재추첨, 중도 이탈의 부분 기억, 참가자의 제한된 보고, 늦은 참여의 실제 시간을 검증했다. `supply_story_browser_smoke.py`는 웹/단독 HTML에서 정상 게임 세계의 실제 현장 진입·세 인물의 단계별 통성명·역할 결정 저장/재개·인수인계와 비참여 일지의 정보 경계를 확인한다. 기존 공개 활동과 미연시 화면의 브라우저 검증도 통과했다. 예시는 `docs/assets/supply-group-preview.png`다.

### 다음 날 연락과 짧은 협력/휴식 장면

지난 봉사 경험이 있는 동료가 직접 보내는 인게임 메시지와 제안 카드를 기존 휴대폰·일정 화면에 연결했다. 수락하지 않은 제안은 참석 예정으로 표시하지 않는다. 실제 약속 장소에서는 만나기로 한 동료와 짧게 함께하는 상황 선택지가 나타나고, 직접 대화 중에도 함께했던 일을 바탕으로 시간을 제안할 수 있다. 현재 기분과 일정에 따라 거절할 수 있다.

‘이어지는 시간’ 장면은 휴식/정리 메모/협력 방식 조율 중 해당 반응으로 진행하며, 두 행동(각 10분)과 작은 마무리로 구성한다. 등장 인물은 실제 현재의 동료 한 사람이고 그의 기존 초상화와 상황별 자세를 사용한다. 별도 이벤트 CG를 새로 생성한 작업은 아니다. 중간 저장 후 메뉴 복귀 카드로 실제 상대가 있는 자리에서 이어갈 수 있다. 장소를 떠났거나 시간 여유가 없으면 상대를 다시 생성하거나 억지로 붙잡지 않는다. 친구끼리 함께 있는 관찰 장면은 보이는 행동만 묘사하고 아직 모르는 이름이나 비공개 사정을 설명하지 않는다.

검증: JS 279개 통과. 실제 경험에 따른 제안/미제안, 수락과 이행 분리, 업무 신뢰와 긴장·휴식의 다른 결과, 큰 긴장의 부분 회복, 고호감도의 일정 거절, 비참여 시 NPC끼리의 동선·시간·정보 경계, 약속 불이행의 일회 반영과 사후 회복, 부분 저장/재개/중복 방지, 자체 모델의 당사자별 문맥, 동료 시간과 플레이어 시간의 중복 방지, 기존 저장 초기화를 확인했다. `supply_aftermath_browser_smoke.py`로 웹/단독 HTML에서 실제 다음 날 시작→메시지→수락→수업→약속 장소→중간 저장/불러오기→20분 이행까지 확인했다. 기존 봉사 사건과 미연시 화면 회귀 검증도 통과했다. 예시는 `docs/assets/supply-aftermath-preview.png`다.
